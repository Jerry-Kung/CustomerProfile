# UAT 合仓部署

直接使用 Docker Compose，配置只维护根目录 `.env`，全部应用共用
`customer-profile-unified:uat`。只构建 `runtime-profile-api` 一次。

## 服务名称

| 服务 | 职责 |
|---|---|
| backend-api | MySQL 任务接口，宿主机 18007 |
| backend-profile-worker | 画像派发与结果跟踪 |
| backend-invitation-worker | 邀约派发与结果跟踪 |
| backend-qingtian-worker | 原擎天目标恢复 |
| backend-commercial-worker | 原商用目标恢复 |
| runtime-profile-api | 画像接单与运行台，宿主机 18000 |
| runtime-profile-worker | 画像实际执行 |
| runtime-invitation-api | 邀约接单，宿主机 8099 |
| runtime-invitation-worker | 邀约实际执行 |
| backend-migrate | 仅新建库时手动执行的迁移 |

容器名采用“服务名-项目名”，例如 `backend-api-customer-profile-runner`、
`runtime-profile-api-customer-profile-runner`，先显示模块和职责。
项目名仍为 `.env` 中的 `customer-profile-runner`，数据卷仍为
`customer-profile-runner_profile-data`。当前 UAT 每服务固定一个容器；增加副本前需移除其
`container_name`。执行器保留 `api`、`inbound` 两个旧网络别名，原配置中的内部地址仍可使用。

## 首次切换

### 1. 旧 backend 目录

```bash
docker compose --profile invitation-runner down --timeout 10
```

旧部署如果指定过 `-p`，使用同一项目名执行。`--profile invitation-runner` 包含可选邀约组，
其他默认服务也一起停止。

### 2. CustomerProfile 目录

先停止旧容器，再更新代码：

```bash
docker compose --profile invitation-runner down --timeout 10 --remove-orphans
git fetch origin
git switch dev
git pull --ff-only origin dev
```

合仓代码已统一到 `dev`，以后以 `dev` 为部署和维护分支。
历史中的 74.45 MiB 镜像 tar 已清除，其余代码历史保留。
根目录 `.env` 不受 Git 管理，更新代码不会覆盖它。原 dev/main 和原 backend 仓库的历史不变。

### 3. 配置、构建与启动

将已合并的 `.env` 上传到 CustomerProfile 根目录；也可从上传位置复制：

```bash
cp /实际上传位置/merged.env .env
chmod 600 .env
docker compose --profile invitation-runner config -q
docker compose build runtime-profile-api
docker compose --profile invitation-runner up -d --no-build --wait
docker compose --profile invitation-runner ps
```

原业务端口、凭据、Runner URL、目标 ID/revision、消费环境、并发与目标模式均保留。
MySQL 使用现有数据库，本次不执行迁移。仅首次新建库时手动执行：

```bash
docker compose run --rm --no-deps backend-migrate
```

### 4. 查看服务

```bash
docker compose logs --tail 100 backend-api backend-profile-worker backend-invitation-worker
docker compose logs --tail 100 runtime-profile-api runtime-profile-worker
curl -fsS http://127.0.0.1:18000/health
curl -fsS http://127.0.0.1:8099/health
curl -fsS http://127.0.0.1:18007/ready
```

健康检查验证启动状态；模型、语音识别及业务回写从正常业务流中观察。

## 以后更新

切换完成后只维护 CustomerProfile 目录：

```bash
git pull --ff-only
docker compose --profile invitation-runner down --timeout 10 --remove-orphans
docker compose build runtime-profile-api
docker compose --profile invitation-runner up -d --no-build --wait
```

只修改 `.env` 时省略构建；`up` 重新创建容器，`restart` 不加载新环境变量。
同一个执行器仍通过独立 Python 环境维护业务后端和工作流模块；MySQL 与 SQLite 状态保持独立。
其他运行约束见[执行器部署说明](部署.md)。

### 更新 LLM 思考参数适配

先取得包含适配修复的代码并修改根目录 `.env`，配置见
[LLM 思考开关](部署.md#llm-思考开关)。这次有 Python 代码变更，必须重新构建镜像。
以下命令在 CustomerProfile 根目录执行，保持原有 Compose 项目名、`CP_ENV_FILE` 与
`--env-file`。本例包含已部署的画像、邀约两组；未启用邀约派发时，去掉
`backend-invitation-worker`，不要为模型切换新建派发组。

```bash
docker compose --profile invitation-runner config -q
docker compose build runtime-profile-api

# 停派发并等待当前任务结束，再让执行进程收敛。
docker compose --profile invitation-runner stop -t 3600 backend-profile-worker backend-invitation-worker
docker compose stop -t 3600 runtime-profile-worker runtime-invitation-worker

# 共用镜像只构建一次；只替换需要此次代码和配置的四个执行层服务。
docker compose up -d --no-build --no-deps --force-recreate --wait runtime-profile-api runtime-profile-worker runtime-invitation-api runtime-invitation-worker
docker compose --profile invitation-runner start backend-profile-worker backend-invitation-worker
docker compose --profile invitation-runner ps
```

`stop -t 3600` 会等待现有任务，超过一小时仍未结束的任务可能被强制停止；长任务部署应
选择足够的停机宽限期。任务的已执行结果和外部副作用不能靠重启自动撤销。

确认执行容器中实际生成的思考参数（不发请求、不输出凭据）：

```bash
docker compose exec -T runtime-profile-worker python -c 'from customer_profile.settings import Settings; from customer_profile.execution.llm import LlmClient; p=LlmClient(Settings()).build_payload("检查参数"); print({k:p[k] for k in ("model","thinking","enable_thinking") if k in p})'
```

上述火山配置应显示 `thinking: {'type': 'disabled'}`，且不包含 `enable_thinking`。
`LLM_ENABLE_THINKING` 留空时两种思考字段都不出现。再观察真实业务任务的运行状态和日志：

```bash
docker compose logs -f --since 10m --tail 200 backend-profile-worker runtime-profile-api runtime-profile-worker
```
