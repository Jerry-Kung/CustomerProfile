## 0. 结论先行

v3.1 把「推导链、说话人、锚点、确定性字段」四处治好了，但它**继承了 v3 的一条准入口径**：
第三方画像数据只算「弱来源」，身份字段仅由它支撑时降为 `inferred_low`、转人工确认。
实测的后果是——**客户没有试驾与沟通记录时，唯一那路画像信源被写进了最不可信的档位**，
下游按低置信处置，字段最终在 Notes 里留白。

v3.2 治两处：

1. **第三方画像标签准入**（用户问题一）：把「第三方画像标签」作为**第三类数据**收进
   L1-1a，某字段由它单独支撑时记 `inferred_high`（不再降 `inferred_low`）。
2. **汽车品牌归属路由**（用户问题二）：L1 提示词显式区分**意向车型**与**竞品**，
   并把 Notes 契约**补挂**竞品对比类的 4 个字段（此前契约里根本没有，信息无处可放）。

v3.2 不做：不动 v3 的三分层与三条接口，不重开 L0/L4，不动 L3，不做通道绑定矩阵。

## 2. 变更一 · 第三方画像标签准入

### 2.1 现象与根因

`13530559591` 的 L0 记录里明确有第三方画像标签（`预测职业司机(小车)`，score 0.985），
但 v3.1 的 `occupation` 全程为空。根因是一条**准入口径**，不是数据缺失：

- 1a 只收两类——`fact`（原文直说）与 `inferred_high`（≥2 条独立来源同向）。一条孤立的
  第三方标签**两类都不属于**，于是 1a 不输出；
- 即使 1c 输出，投影层规则 b 见「身份字段仅由预测支撑」，按 v3 口径降 `inferred_low`；
- 兜底层对 `missing` 字段只能从**已定稿事实表**归纳，而事实表里本就没有 `occupation`；
- 审查层再把「未知」这类占位串清掉 → 字段在 Notes 里彻底消失。

### 2.2 决策（用户口径）

**第三方画像标签是采购来的商用画像数据**，在客户没有试驾与沟通记录时，它是**唯一较为
可靠的画像推理信源**。因此：

- 1a 准入新增**第三类**：某字段只要有单独的第三方画像标签支撑，就收进来，记
  `basis=inferred_high`，来源档记 `第三方画像数据`；
- 投影层规则 b 对「仅预测支撑」的身份字段**改记 `inferred_high`**（既不降级、也不转
  人工确认）；
- `_basis_of`（离线回放旧产物时的档位回推）与 `Claim.effective_basis`（来源档与自述档
  冲突时取更弱者）同步改口径：预测渠道**封顶在 `inferred_high`**，但仍**不是** `fact`。

### 2.3 为什么预测仍不等于 `fact`

`fact` 的语义是「客户原话可直接回溯」；画像标签是**统计预测**，没有客户自述锚点。
把它直接写成 `fact` 会重演基线那类错误（把第三方预测当客户事实）。因此 v3.2 的落点是
**升到中间档**，而不是升到最高档。

## 3. 变更二 · 汽车品牌归属路由 + 契约补挂

### 3.1 现象与根因

`18898883341` 的记录里有客户试驾时提到其它品牌的线索，但 v3.1 全程未出现。

根因有两层：

1. **提示词层**：brand/车型 出现时，L1 没有「这属于意向还是竞品」的判据，只能塞进
   `intended_model` 或干脆不写；
2. **契约层（决定性）**：`_to_notes_updates` **只遍历契约字段**，而仓库冻结的 42 字段
   契约里**根本没有竞品字段**——任何竞品信息都写不进 Notes，即使 L1 检出了。

> 对用户「Notes 中原生设有意向品牌与竞品对比类字段」的判断：**结论成立，键名需按契约**。
> 实测线上契约里竞品类的键是 `competing_brand` / `competing_model`（外加
> `test_driven_models` / `brand_concerns`），归在「竞品对比」分类下；用户所提到的
> `comparison_brand` 等拼写是**基线模型自造的非契约键**，所以永远进不了 Notes。

### 3.2 决策

- **提示词（1a/1c）**：新增「汽车品牌与车型的归属判断」口径——意向车型、对比品牌/车型、
  试驾过的车型、本品牌顾虑，各自落到对应字段；**归属拿不准时写进对比类字段比漏掉好**，
  但不得把随口路过的品牌塞成 `intended_model`。
- **品牌知识**：**先以 LLM 原生汽车知识为准**（辨识品牌 vs 车型、纠正 ASR 音近错字，
  如「领跑」→「零跑」、「安安」→「埃安」）。**知识库仍在筹备中，建成后接入**——
  当前不得因拿不准品牌名而整条不写。
- **契约补挂**：竞品对比类的 4 个文本字段补进快照（详见 §4）。
- **聚合语义**：竞品四字段入 `AGGREGATE_TEXT_KEYS`——客户在多个品牌/车型间对比是常态，
  判冲突会把整字段留白；`test_driven_models` 的契约描述本就写着「提取车型名，**可多个**」。

### 3.3 明确不动的一条

`customer_name` 的来源白名单（只认一手自述 / 登记）与 `title` 的弱来源降级**保持原样**。
理由：预测正确的人名收益极低，错的人名代价极高（与 v3 接口二同口径）；性别标签的可靠
性问题与画像标签不同类，不在本次放开范围。**v3.2 放开的是预测撑「可推断的属性字段」
（职业、收入量级、人生节点等），不是身份标识类的硬字段。**

## 4. 契约变更明细（对外契约）

**这是 v3.2 唯一一处动到对外契约的地方，需评审。**

| 项 | 变更前 | 变更后 |
|---|---|---|
| 字段数 | 42 | **46** |
| 分类数 | 5 | **6** |
| 新增分类 | — | **竞品对比**（4 个文本字段） |
| 新增字段 | — | `competing_brand`（对比品牌）、`competing_model`（对比车型）、`test_driven_models`（试驾过的车型）、`brand_concerns`（本品牌顾虑） |
| 枚举字段数 | 21 | 21（新增 4 个全是文本） |
| 单选 / 多选 | 16 / 5 | 16 / 5 |

**落法**：基线快照（42 字段，签名 `0479e326bc88`，2026-09-29 固化）**不动**，新增字段走
**补充文件** `src/customer_profile/notes_contract_extension.json`，由
`scripts/snapshot_note_contract.py` 合并生成快照。生成器与 `--check` 均已扩展。

**为什么不整表换用线上 45 字段**：线上契约在新增这批字段的同时**下线了 16 个现役字段**
（`old_car_model` 被确定性注入依赖、`intended_brand` 被 18 处引用、`emotion` 等被
v3.1 判据引用）。整表替换会**静默打掉已完成的功能**，超出本次诉求。整表迁移另开任务。

## 6. 风险与回退

| 风险 | 处置 |
|---|---|
| 预测升档后，销售把预测当客户事实 | 仍标 `inferred_high`（非 `fact`），置信度 0.7（非 0.9）；且不写进任何 `fact` 才允许的位置 |
| 1a 把标签名连 JSON 标点抄进 `anchor`，被噪音门收回 | 提示词明写「只抄标签名、不抄 `{"name": `」，并给正例 |
| 1a 只给 `reasoning_chain` 不给 `basis_of_inference` → 定位层降 `inferred_low` | 提示词明写该字段**必填**并说明原因（实测踩过） |
| 品牌归属判错（把竞品写成意向） | 提示词规定「拿不准归对比类」——漏判代价小于误判；知识库建成后收紧 |
| 契约补挂未同步到写回端 | 本文 §4 单列，需与 Note 服务确认写回端是否已支持这批键 |
| 回退 | 两处改动分别可独立回退（提示词与档位；契约扩展文件与生成器开关） |
