# v3.3 全量基线跑批操作指南

## 快速开始

### 1. 小批量测试（推荐先做）

验证环境和代码是否正常：

```bash
# 只跑1个号码，快速验证
python scripts/run_baseline.py \
  --workflow-id customer_profile_pipeline \
  --phones experiments/batches/baseline-39-dsv41-noThink/phones.txt \
  --limit 1 \
  --retry-failed 1

# 检查结果
ls -lh experiments/batches/baseline-v3.3-final-*/
```

预计耗时：2-5 分钟

### 2. 全量39用例跑批

确认测试通过后，执行全量跑批：

```bash
python scripts/run_v3.3_baseline_full.py
```

脚本会：
1. 自动读取39个手机号清单
2. 跑完后复制结果到 `docs/business_opt01_v3/baseline-v3.3-final/`
3. 生成数据说明书（README.md）
4. 验证 v3.3 改进是否生效

预计耗时：30-60 分钟

### 3. 验证结果质量

跑批完成后，验证数据是否可用于制作结果页面：

```bash
python scripts/validate_v3.3_results.py
```

检查项：
- [x] 文件结构完整
- [x] 成功率 >= 95%
- [x] v3.3 改进生效（anomaly/finish_reason 字段）
- [x] 结果质量合格

## v3.3 可靠性改进

跑批自动应用以下改进：

1. **自动重跑**: `--retry-failed 2`
   - 失败案自动重试最多 2 轮
   - 每轮退避 60 秒
   - 直接消除瞬断损失

2. **异常诊断**: 
   - `trace.db` 记录 `anomaly` 和 `finish_reason`
   - 可事后分析异常原因

3. **参数校验**:
   - 检查 workflow_id 匹配性
   - 检查转写缓存配置

4. **输出量闸门**:
   - 检测 `finish_reason` 异常
   - 防止输出塌陷静默通过

详见: `CHANGELOG-v3.3-reliability.md`

## 常见问题

### Q1: 转写缓存命中率低怎么办？

检查缓存目录：
```bash
ls -lh experiments/transcript_cache/
```

如果缓存为空或过旧，首次跑会全部 miss，后续跑批会复用。

### Q2: 部分用例失败怎么办？

1. 查看 `summary.md` 找到失败的号码
2. 查看 `runs/{phone}/result.json` 的 `error` 字段
3. 查看 `trace.db` 的 `request_attempts.anomaly` 诊断异常
4. 如果是偶发故障，会在自动重跑中恢复

### Q3: 如何补跑特定号码？

```bash
python scripts/run_baseline.py \
  --workflow-id customer_profile_pipeline \
  --batch-id baseline-v3.3-final-<timestamp> \
  --only 13415100087,13430349943 \
  --resume
```

### Q4: 如何查看 v3.3 改进是否生效？

```bash
# 检查数据库 schema
sqlite3 docs/business_opt01_v3/baseline-v3.3-final/trace.db \
  "PRAGMA table_info(request_attempts)" | grep -E "anomaly|finish_reason"

# 查看异常记录
sqlite3 docs/business_opt01_v3/baseline-v3.3-final/trace.db \
  "SELECT COUNT(*) FROM request_attempts WHERE anomaly IS NOT NULL"
```
