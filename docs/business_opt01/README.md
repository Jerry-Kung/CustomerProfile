# 业务输出优化（business_opt01）

> 本目录存放「客户人设画像输出质量优化」这一条工作线的**文档与工具**。
> 代码改动暂不落在主干上，见 §6 的工作方式。
> 目录规范见 `../README.md`；本目录是一次业务优化的**工作区**，收口后按规范归档。

## 1. 我们要解决什么问题

**一句话：工作流给出的客户人设画像不够准确，会误导销售、导致丢单。**

客户人设画像业务基于「公开渠道搜集的客户数据 + 销售与客户的初步接触记录」，为潜在客户
建立一张个人画像，帮助销售人员快速掌握客户基础信息、制定针对性销售策略。

产出分两部分，都在本次优化的范围内：

- **Notes 更新项**（`basic_notes_updates`）：结构化字段，最终回写到 Notes 服务；
- **客户画像卡**（`profile_summary` / `inferred_tags` / `usage_scenarios` /
  `communication_strategies` / `customer_overview` / `emotion_state` /
  `purchase_motivations` / `product_preferences` / `resistances`）：给人读的画像正文。

**为什么严重**：画像是销售人员做判断的直接依据。画像错一处，销售就可能朝错误方向使劲——
判错购买类型会让置换方案落空，判错职业会影响话术与车型推荐，判错预算会报错价。这不是
「体验不佳」，是**业务功能失效**，风险等级为「关系项目生死」。

## 2. 销售人员反馈的三类问题（本次优化的起点）

来自先前收集的真实使用反馈：

1. **不同字段相互矛盾**。例：Notes 的「旧车车型」识别出有旧车，「购买类型」却仍填「首购」。
2. **信息错误**。例：某客户职业判为「电力局职工」，但复盘外呼/试驾原始录音，实际是
   **客户的妻子**在电力局工作。尚不明确信息在哪一步丢失或错配。
3. **证据链/推理链乱写**。多数字段带 `reasoning_detail`（`summary`/`steps`/`evidence`/
   `confidence`），但常出现：「证据信源」里写的不是信源而是二次加工内容；`evidence` 与
   `steps` 各说各话；推理链与正文 `summary` 毫无关联，或看不出任何推理逻辑。

## 3. 基线诊断结论（详见 `基线画像质量诊断.md`）

我们对 39 份用例的基线批次（`baseline-39-dsv41-noThink`）做了全量诊断。**三类反馈全部复现**，
另发现若干同类缺陷：

| # | 问题 | 规模 | 性质 |
|---|---|---|---|
| 1 | 枚举字段填中文而非枚举键（如 `"油耗\|\|安全"`） | 8 字段 / 38 处 | 契约违规，下游匹配失败 |
| 2 | 同一语义被拆成多个 `attribute_key` | 23 个 key | 数据分散，聚合漏数 |
| 3 | `purchase_type` 缺失 / 与旧车信息矛盾 | 12 案缺失 + 多值 + 换购无证 | **反馈①复现** |
| 4 | `deal_level` 与 `business_opp_level` 冲突 | 4 案 | 销售看到两个等级 |
| 5 | 证据锚点引用自产画像（信息匮乏时凭空造证） | 20/4531 | **反馈③复现** |
| 6 | 证据锚点用「第三方画像预测」冒充客户事实 | 737/4531（16.3%） | **反馈②③** |
| 7 | 上游证据描述含主观推断词，仍有 16 条评 A 级 | 316/1283（24.6%） | **反馈③复现** |
| 8 | 「录音：」引文约 1/3 无法回溯到原文 | 465 条中失配 ~1/3 | **反馈③复现** |
| 9 | `summary` 与 `steps`/`evidence` 零语义重叠 | 333/2227（15.0%） | **反馈③复现** |
| 10 | `occupation` 靠第三方画像预测、注销企业照填 | 10 案 / 1 案 | **反馈②复现** |
| 11 | 年龄格式不一致（15 案）、姓名/微信号脏值 | — | 一致性与数据卫生 |

**同时确认了哪些没坏**（优化时不应误伤）：结构完整（2227 个 `reasoning_detail` 无缺字段）、
0 条使用 `ev_XXX` 证据 ID、标签 0 条超 8 字、置信度 0 条越界、证据分级硬规则零违规。
**格式类约束提示词写得住，语义类约束写不住——优化重心在后者。**

## 4. 优化目标与非目标

**目标**（按验收优先级）：

1. 消除**事实性错误**与**字段间矛盾**——这是最致命的一类，优先级最高。
2. 让**证据链可信**：证据锚点必须能落到原始证据上，不得引用中间产物或统计预测冒充事实。
3. 让**推理链自洽**：`summary`/`steps`/`evidence` 三者内容一致、可读、有推理逻辑。
4. 让**输出满足下游契约**：枚举键、字段名、格式与 Notes 模板一致。

**非目标**（明确不做，避免范围蔓延）：

- 不改工作流的**结构**与节点编排（本轮只优化内容与约束）；
- 不改注释/回写协议与生产库；
- 不追求「画像更丰富」——本轮只解决「不准」。
