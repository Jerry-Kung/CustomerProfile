# 任务清单与计划

## 总览

| 期次 | 主题 | 目标 | 依赖 | 产出 |
|---|---|---|---|---|
| 0 | 止血 | 停止输出埃安产品内容 | 无 | 换掉两份产品资产、去品牌化邀约策略 |
| 1 | 骨架 + 闭集 | 知识包可加载；意向车型闭集；运行台可见 | 0 | `knowledge/` 包、猛士知识包、两个视图、K5 分流、K6 页面 |

## 实施顺序的硬约束

1. **第 0 期先于第 1 期**。否则排查时分不清「知识没接上」与「接上了但内容还是错的」。
2. **T1-1、T1-2 先于 T1-4、T1-5、T1-6、T1-7**。后四者都依赖加载与解析。
3. **T1-3 可与 T1-1 并行**，但 T1-6 必须在 T1-3 之后——表达视图要有条目可读。
4. **T1-5 必须在 T1-3 之后**。闭集判定的正确性完全取决于清单是否完整。
5. **T1-7 可与 T1-4~T1-6 并行**，只依赖 T1-6 的 `build_payload` 数据结构。
6. **每期结束跑一次小批**。全量批只在 A/B 对照时跑。

## 回滚策略

| 粒度 | 方式 |
|---|---|
| 单条规则 | `RULES_DISABLED=KB-02` |
| 知识能力 | `KNOWLEDGE_PACK` 指向空包 → 视图输出空串，分流跳过，行为回到改动前 |
| 前端页面 | 移除标签页（不影响后端与其他功能） |
| 整期 | `git revert` 该期提交。第 0 期与第 1 期分开提交，不合并 |

「空包」是刻意设计的回滚口：加载一个只有清单、没有车型的包，两个视图都输出空串，
管线行为与未接入知识时一致。**这比代码开关可靠——开关会腐烂，数据不会。**
