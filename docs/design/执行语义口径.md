# 执行语义口径

> 本文记录**执行器的行为契约**：那些「代码里只有一行实现、读不出为什么」的判断。
> 每条都标出固化它的测试。改动任何一条都等于改动运行时语义，须先读这里的理由。

这些口径原先记在迁移台账的 `differences.md` §2（P 系列 / M 系列 / Q 系列）。台账已随迁移
收口删除，契约迁入本文。**P 与 M 的每一条都已在代码中实现并有测试固定**；Q 系列中已获外部
结论的部分记为「已确认」，其余为「缺省采用」——后者是**实现依据，不是等价验证通过**。

## 1. 迭代节点（P 系列）

### P1：迭代按串行执行，`is_parallel` 是权威信号

迭代节点同时带 `is_parallel: false` 与 `parallel_nums: 10` 两个参数。**按串行实现**：
`is_parallel: false` 是权威信号，`parallel_nums` 在其下不生效。

- 依据：8 个迭代节点的 `is_parallel` **全为 `false`**（迁移期实测）。
- 各轮执行按 `call_path`（`<父路径>/iter:<id>/<index>`）区分并逐项留痕。
- 固化：`tests/test_iteration.py`。

### P2：某一项失败即终止整轮，且已完成项的结果保留

迭代节点的 `error_handle_mode` 全部为 `terminated`（8 处实测）。实现为「某项失败即终止
整轮」，错误信息指明失败项序号，下游按既有口径阻断（`BLOCKED`）。

**已完成项的结果保留**——终止不等于回滚。`BLOCKED` 是**故障**语义（前置失败、结果不可信），
与 `SKIPPED`（未走这条分支）严格区分。

- 固化：`tests/test_iteration.py::test_iteration_stops_on_first_failure`。

### P3：分组聚合的每组包 `{"output": 值}`

`variable-aggregator` 开启 `group_enabled` 时，输出是**多字段对象**，键为组名，**每组的值
不是裸值，而是 `{"output": 值}`**。

- 依据：下游 `code` 节点取的是 `hobby_result_object["output"]`，且这些入参在定义里声明为
  `value_type: object`。
- 未分组时输出字段名缺省为 `output`（与迁移前定义的默认输出名一致），可由 `config["output"]` 覆盖。
- 固化：`tests/test_aggregator.py::test_grouped_aggregator_wraps_each_group_in_output`。

### P4：聚合取值判据是「执行过」，不是「非空」

`if-else` 两侧分支汇聚到同一 `variable-aggregator` 时（出现在人设特征判断与各截图类工作流），
取「第一个**真正执行过**的输入」，判据是 `ctx.has(node_id)` / `ctx.resolve_optional` 的哨兵值，
**不是**「值非空」。

- 为什么这条重要：**空串是合法产出**——`无数据，输出默认信息` 模板的正常结果、各截图流程
  code 在未命中 channel 时明确返回空串。按非空判定会把这些正常结果误判为缺失，**静默改用
  另一支的值**，而运行仍显示成功。
- 一个来源都没执行过时**如实报错**，不用空串伪装成成功——那会让下游拿着一个来源不明的
  空值继续跑。
- 固化：`tests/test_aggregator.py::test_aggregator_takes_first_executed_even_when_empty`。

### P5：HTTP 状态码 ≥400 即失败，可用兜底改为不失败

`HttpAttempt.succeeded` 要求 `error is None and status_code is not None and status_code < 400`。

节点可用 `@error_strategy: default-value` 改为取兜底值而不失败。超时与重试参数一律走显式
配置（见 Q5），**不把定义文件里的原值直接传给 HTTP 库**。

- 固化：`tests/test_api.py`（`HttpAttempt.succeeded` 实现路径）。

## 2. LLM 调用（M 系列）

### M1：最多 3 次尝试（首次 + 2 次重试）

`MAX_ATTEMPTS = 3`。这是**缺省口径而非已核实协议**——「3 次尝试」究竟指「最多 3 次」还是
「首次 + 3 次重试 = 4 次」，始终没有外部结论。沿用原标记方式，**不写成「已确认」**。

重试下沉在 `llm_call()` 内部（迁移前它是图上的一个子流程）。因重试不再由图结构天然分开，
**每次尝试独立写入 attempt 表**——否则「17 处调用的每一次尝试」这件事无从验证。

- 固化：`tests/test_llm_retry.py`、`tests/test_node_attempts.py`。

### M2：`expect_json` 由调用点显式声明，不做推断

迁移前定义的 `tool` 节点的 `output_json` 入参**全部为 `false`**，无法据此判断任务是否需要
JSON 输出。因此**不继承该字段**，改为按「下游消费方语义」逐点声明：下游 `code` 对其输出做
JSON 解析、或提示词明确约定输出 JSON，即 `expect_json=True`。

- 固化：`tests/test_expect_json_output.py`。

### M3：模型必须支持多模态（硬约束）

全项目 **12 个 vision 节点**要求所选模型具备多模态能力。它们全部位于截图解析类工作流，
以 http 节点的 `files` 字段（data URI 列表）为输入。

- `.env` 的 `LLM_MODEL` 选型时必须确认这一点。
- 上游没有图片时返回 `None`，由调用方按「非 vision 调用」处理——**不伪造空图片列表**。
- 图片字节优先取**原始字节**：用解码后的文本再编码会产出与真实文件不一致的 base64
  （实测 PNG 头被改写），而模型侧只报一句语焉不详的下载失败。

## 3. 外部接口与协议（Q 系列）

### 已获外部结论

| 编号 | 问题 | 结论 | 落地 |
|---|---|---|---|
| Q1 | 回写接口的成功判定 | **2xx 即业务成功**（用户 2026-09-24 答复） | **顺延至幂等回写版本**。现实现只记 HTTP 状态与响应体 |
| Q2 | 回写是否支持幂等键 | **支持，粒度 = 客户**（用户 2026-09-24 答复） | **顺延至幂等回写版本**。现实现不自动重试 POST |
| Q7 | 现有调用方协议 | **沿用当前 API 层**（用户 2026-09-24 答复） | 不改对外契约。队列模型的 429 触发条件变更属行为微调，入参形状与成功返回值不变 |

Q1/Q2 的落地前提是**幂等回写**。在该能力落地前，`WRITEBACK_ENABLED` 缺省为 `false`，
回写节点只产出「已跳过」的可解释结果——这样可以在没有幂等保证时避免重复副作用。

### 缺省采用（实现依据，非等价验证）

| 编号 | 问题 | 缺省处理 |
|---|---|---|
| Q5 | HTTP 的 `timeout: 0`、`retry_interval`（无单位）、`max_retries: 3` 的运行语义 | 改用显式配置：连接 10s / 读 600s、间隔 500ms。**不把原值直接传给 HTTP 库** |
| Q6 | 语音服务轮询的终止条件与最大次数 | 按有限次数上限实现（间隔 1s、上限 1800 次，即 30 分钟封顶） |
| Q8 | 峰值请求率、单任务调用数与 token 量、期望时延、留痕保留期 | 保守默认值 + 配置化。`MAX_QUEUED_RUNS=50` 是保守值，**非压测结论** |

**注意**：Q 系列属外部接口与协议。P 系列（平台语义）与 M 系列（模型口径）**不在「缺省采用」
的覆盖范围内**，它们各自的依据见上文各条。
