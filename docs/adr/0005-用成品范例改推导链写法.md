# ADR 0005：用成品范例改推导链写法，以及三条随之定下的硬边界

- 状态：已采纳（2026-11-16，分支 `dev-rules-opt01`）
- 相关：`src/customer_profile/templates/customer_profile_pipeline__pipeline_l1_fields.txt`、
  `src/customer_profile/templates/customer_profile_pipeline__pipeline_l1_facts.txt`、
  `docs/architecture.md`、`docs/遗留问题清单.md` L-014

## 背景

销售反馈画像里的「信源」与「推导链」看不懂。问题不在准确率——值多数是对的，问题在
**可读性与可核查性**。在 UAT 批次上量化后，有三类病灶：

| 病灶 | 表现 | 实测 |
|---|---|---|
| 循环论证 | 信源把结论复述一遍，没指向行为或语境 | 14%–38% |
| 空话式总结 | 「有原文依据：…」「根据客户资料中已有信息归纳得出」 | 每份 20–48 项 |
| 推导链退化 | 平均 1.38–2.0 步，多为一句话把依据再说一遍 | 论据与论证没分开 |

试过的办法是「在提示词里要求写得更可读」，作为形容词没有约束力。本轮改为给模型
**成品范例**做上下文学习，并把人写范例时总结出的写法固化成模板。

## 决策一：范例注入 L1 字段层，不在出口层

管线是 `L1 事实 → L1 人设 → L1 字段 → L2 → 回传构造`。三种注入方案里，**出口层注入不成立**：
`reasoning_detail` 的 `summary` / `steps` / `evidence` 由 `projection._readable_summary` /
`_readable_steps` / `_readable_evidence` **用代码渲染**，那里没有 LLM 环节可注入。

| 方案 | 结论 |
|---|---|
| A. 注入出口层 | **否决**。出口是代码，注入后跑出来会「毫无变化」，然后被误判成「范例法无效」 |
| **B. 注入 L1 字段层** | **采纳**。取证阶段就产出可读写法，与「推导链由模型写」的既定分工一致 |
| C. 单独一道「改写」工序 | 不做。多一次调用，且与「本轮只调提示词」的实验边界不符；B 单独跑不出效果时再评估 |

> 这条查证本身比结论更重要：先确认「要改的东西是谁写的」，否则整个实验会建立在一个
> 假前提上。

## 决策二：四段式是软要求，不是格式

推导链统一按 **信源整合 / 信息缺位 / 结论推断 / 检查核对** 四个环节组织，标签直接写在句首
（前端按前缀识别与着色，因此前缀必须逐字使用）。

三条约束让它不至于变成新的八股：

- **某环节没有有效内容就整条省略**，不许写「信息缺位：无」凑格式；
- **现取现用的字段只留必要环节**（手机号、消费等级这类抄来的，写两段即可）；
- **`fact` 条目同样要写推导链**。这一条推翻了旧规则「`fact` 不必给，锚点本身就是路径」——
  销售反馈恰恰是**锚点本身看不懂**，「客户说了一句什么话」不等于「这句话足以支撑这个结论」。
  旧假设被使用方推翻，规则一并改掉。

## 决策三：范例按字段取，不整份注入，且必须脱敏

**按字段取**：只注入 `reasoning_detail` 片段，同一字段取 1–2 条，推断难度高的取两条。

| 取舍 | 理由 |
|---|---|
| 不整份塞 | 整份 6 例约 6.7 万字，吃上下文，且模型容易把别家客户的故事抄进来 |
| 同字段优先取**最短**的合格写法（三段以上、来自不同样本） | 拿最啰嗦的一条当范本，会把字数标准抬歪 |
| 能从输入直取的字段**不给范例** | 给了只会教模型把简单事写复杂 |
| 相邻字段尽量出自不同样本 | 避免模型把某一个人的经历当成模板 |

最终范例块 1.18 万字，模板从 1.18 万涨到 **1.92 万**字；模型单次输出预算 128k token，
不构成压力。

**脱敏是硬要求**：提示词受 Git 管理，范文里不得出现真实客户的姓名、手机号、企业、门店、
住址。做法是把可识别实体换成**同构的虚构值**（结构、角色、话术长度逐条保留——范例的
价值在写法不在内容），并做三道自检：手机号残留、真实地名/人名残留、替换叠字
（如「某省省」）。替换必须**按长度倒序**，否则「湖北」先于「湖北省」被替换会留下叠字。

**脱敏不覆盖品牌与车型名**（2026-11-17 补充）。这是当时漏划的一类，现在明确边界：
`competing_brand` / `competing_model` / `intended_model` / `test_driven_models` 这些字段的
范例，**必须**写出具体品牌车型——写成「某竞品A」就失去了示范取值域的作用。因此范例里的
品牌名按**合法举例**处理，走 `brand_exemptions.json` 豁免，而不是替换成虚构值。

代价要说清楚：品牌名残留守卫会把它们报出来，需要为模板文件
`customer_profile_pipeline__pipeline_l1_fields.txt` 逐品牌维护豁免条目（豁免是「路径 + 品牌」
成对生效）。范例里每新增一个竞品名，就要补一条——这是守卫刻意保守的结果，不是遗漏。

## 决策四：三条硬边界（跑批暴露后才补上的）

前三轮跑批各暴露一类「学会写法但学歪了」的问题，逐条转成硬边界：

| 问题 | 实例 | 规则 |
|---|---|---|
| 枚举字段被写成 `unknown` | 7 个字段写 `unknown`/`未知`，而 `unknown` 只在 `knowledge_of_*` 与 `electronic_ecosystem` 是合法键 | 列出允许写 `unknown` 的四个字段，其余「要么给出能落地的取值（哪怕置信低），要么整条不输出」 |
| 不写 `unknown` 就写空 | 5 个字段输出空字符串 | 空字符串、`null`、「暂无」「待确认」与不输出等价，但下游会当结论渲染；**没内容就整条不出** |
| 同品牌占用竞品位 | 客户在 M817 与 X700 间选型，`competing_brand` 写成「猛士」 | 同品牌内选型 `competing_brand`/`competing_model` **整条不输出**，不得以「说明性记录」名义填写 |
| 主语归属判错 | 客户在说自己儿子「在部队是文职」，被写成客户 `industry`/`occupation` | 先判断这句话在说谁；家属信息**不得**写进客户字段 |

**这四条都不是凭空想出来的**，是逐字段人工复核 87 处取值变化、逐条回原始输入核对方向
之后才发现的。只跑机器指标看不出来——`unknown` 那条甚至表现为「字段数正常，只是少了几项」。

## 决策五：验收指标的口径（两个教训）

**教训一：`summary` 不能作为提示词效果的判据。** 它由 `_readable_summary` 用代码拼成
（`有原文依据：{quote}`），提示词改不了它。改看「这句模板后面有没有模型写的推导链」：
175 条模板句里 160 条模型写了 ≥2 步，基线同类只有 15/385。要让 `summary` 本身变好，
必须动出口代码——那是方案 C，不在本轮。

**教训二：「字段名：值」式循环论证有两类，不能合并统计。** 引用结构化登记字段
（`线索当前阶段：…`、`订单记录：…`）是合法写法，`客户原话：…`/`销售原话：…` 是
`projection` 家加的说话方前缀；真正的循环论证只占其中一部分。两臂不统一口径，
这个指标就不可比（同一份数据改名前后能差 7 个百分点）。

## 结果

同一批 5 个未参与范例制作的号码，三种输入形态各覆盖，同一归档输入重放：

| 指标 | 基线 | 首轮（范例） | 终轮（补三条规则） |
|---|---|---|---|
| 出口字段覆盖 | 186 | 199 | **198** |
| 四段式条目 | 0 | 270 | **268**（其中三段以上 132） |
| 平均推导链步数 | 1.97 | 2.71 | **2.66** |
| 真循环论证率 | 14% | 18% | **14%** |
| 引文逐字命中 | 124 | 134 | **138** |
| 非法 `unknown` | — | 11 | **0** |
| 空字符串取值 | — | — | **0** |
| 跨客户内容串写 | — | 0 | **0** |

## 代价与后续

- **提示词体积增长 62%**（1.18 万 → 1.92 万字），含 1.18 万字范例块。若日后要压缩，
  先砍「能从输入直取」的字段范例，那里收益最低。
- **主语归属只解决了一半**：`15102795655` 的 `industry` 仍写成部队系统，根因在**跟进记录
  本身**（「客户自己是部队的比较关注」有歧义，模型据此判为客户本人）。提示词层面到此为止，
  要根治得让销售把头写清楚。
- **长提示词 + 多字段 JSON 输出下有一过性波动**：某号码一轮只产出 13 个字段并自造了
  `driving_preference_placeholder` 空字段，同条件重跑即恢复 27 个字段。**建议在解析侧加兜底**：
  丢弃 `*_placeholder` 这类非契约键与空值条目并记降级日志——见 `遗留问题清单.md` L-014。
- 范例块由脚本从范例 JSON 按字段抽取生成，不是手抄；日后范例更新应重跑生成而不是改模板正文。
