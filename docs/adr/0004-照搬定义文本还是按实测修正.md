# ADR 0004：照搬迁移前定义的正文与绑定，还是按实测事实修正

- 状态：已采纳（2026-09-28 / 2026-09-29 业务方与用户确认）
- 相关：`docs/architecture.md` §6；`docs/changelog.md` 2026-09-27 与 2026-09-24 两节

## 背景

本项目的工作流定义来自低代码平台的 DSL 迁移。迁移的既定口径是「**正文逐字符一致**」：
包内模板资源（`src/customer_profile/templates/`）与 code 节点正文都不改动，确需改动必须
显式登记理由并获确认。这条口径有它的道理——它让「迁移有没有把逻辑改坏」这个问题可以被
机械地验证，而不是靠人读。

2026-09-28 业务方提供修订版 DSL（三份文件：证据线索汇总、极光数据、新增手机号&企业信息
分析），2026-09-29 又确认两处 code 正文修订。这批改动里，**多数是照搬新版即可**，但有
四处是「照搬会错」：定义文本与实际接口载荷不符，照搬的后果是数据被静默丢弃而运行仍显示
成功。本 ADR 记录这几处的取舍。

前身是迁移台账的 `differences.md` §1.7（W44–W52）。台账已随迁移收口删除，业务价值内容
迁入本文档。

## 决策一：结构性改动照搬（无取舍）

以下三条**没有争议**，照做即可，记录在此只为保持这批改动的完整：

- **新增子流程「手机号&企业信息分析」（`phone_company_analysis`）**，8 节点 / 8 边。原先
  散在「证据线索汇总」里的四节点（取关联企业 → 拆运营商/企业 → 两个 LLM）整体迁入。
  该图用分组聚合器（每组包 `{"output": 值}`），下游「聚合结果拆壳」取 `["output"]`；
  **两个 LLM 的输出字段是 `text` 而非 `result`**——与其它 llm 节点形态不同，照抄会静默取空。
- **「证据线索汇总」结构随之变化**：24 节点 / 39 边 → 21 节点 / 35 边，主图改用一个
  `tool` 调用点承接上述子流程。
- **「客户数据聚合」模板新增字段 `第三方画像数据`，绑定极光数据。** 此前极光结果**根本没
  有进聚合包**——这是一处功能性修复，不只是字段增补。
- **极光数据子流程的 `data_source` 默认值由 `jiguang` 改为 `DatametInterestPoints`**，
  上游证据汇总图同时改为显式传参同名值。旧值取不到该渠道数据。

## 决策二：三处正文偏离定义文本（本 ADR 的核心）

以下三处的**定义文本本身是错的**。照搬等于把一个「静默丢数据」的缺陷原样带进新实现。
处置方式是：**改动正文，并按既有口径显式登记为偏离**，同时保留回归用例。

### 偏离一：企业信息解析的取值键（节点 `1774941932987`）

- **定义文本写的**：按 `operator_location_json` / `affiliated_company_json` 取值。
- **实测事实**：`RelatedEnterpriseInfo` 渠道的真实载荷**从不含这两个键**。全部留痕实测
  （5 个批次 / 8 份响应）出现 0 次，仓库内也没有任何节点产出它们。
- **照搬的后果**：`operator_location` 与 `affiliated_company` **恒为 `{}`**，企业信息分析
  LLM 只能回「输入数据为空」，**真实企业数据被静默丢弃**（某号码的 `business_info` 里有
  完整企业名称、法人、注册号，全部被丢掉），而运行整体仍是 `succeeded`。
- **现取值**：归属地取 `operator_location`；企业内容按 `company_main` / `company_detail` /
  `business_info` / `enterprise_base_info` / `shareholder_info` **逐块收集，只收有实内容的
  块**；并保留对定义文本原键名的兼容读取。
- **为什么不是「改成新键名」而是「两种都收」**：渠道载荷有两种实测形态（企业查询有结果 /
  天眼查），且无法保证未来不会退回旧形态。逐块收集 + 兼容旧键名让两种形态都能工作，代价
  只是一段并列的取值代码。

### 偏离二：辅助函数 `_parse_json` 的围栏识别条件（节点 `1778232215760`）

- **定义文本写的**：只认「整段以 ``` 开头」的代码块包裹（`text.startswith("```")`）。
- **实测事实**：模型常见输出形态是「一句说明 + 换行 + ```json 块」——这类输出既不进剥围栏
  分支，又无法被 `json.loads` 解析，整体落入 `except` 返回空 dict。
- **照搬的后果**：**解析失败与「确实无数据」在下游无法区分**。基线批次
  `baseline-39-dsv41-noThink` 的 39 个号码中有 2 个因此丢失 `wechat_profile_info` 字段，
  而运行整体仍是 `succeeded`。
- **现行为**：围栏不在开头时按**第一个**围栏块提取；无成对围栏时返回 `None`、沿用原文，
  **不猜**。
- **这是全项目第一处辅助函数偏离**：原先的逐字符比对只管 code 节点的 `main`，因此本处
  新增了一个独立的登记通道，避免它被「main 一致」的断言掩盖。

### 偏离三：模板「客户数据聚合」的 `关联企业信息` 绑定

- **定义文本渲染的是**：`{{ phone_result }}`，而绑定表为它提供的是 `company_result`。
- **照搬的后果**：**企业分析结果被丢弃、该字段实际装的是手机号归属地分析**。迁移前的
  DSL 同样如此，非本轮引入。
- **现行为**：改为 `{{ company_result }}`。
- **为什么单独登记**：这是全项目**唯一的模板正文有意偏离**。正文改动属业务优化，按既有
  口径须单独提出并获确认——本轮已取得用户确认。

## 决策三：模型参数可配置（`LLM_ENABLE_THINKING` / `LLM_MAX_TOKENS`）

- **背景**：既定要求是「不设其他参数」，沿用服务端默认。
- **实测**：关闭思维链后，服务端在不指定上限时把输出**卡在 8192 token**
  （`completion_tokens=8192`、`finish_reason=length`），而该节点需要约 2.9 万 token 的 JSON
  正文，会被拦腰截断；且异常检测**不检查 `finish_reason`**，截断会静默通过异常检测、
  在下游解析时炸掉。
- **决策**：新增两个可配置项，缺省均为 `None`，即**不发该键**——「不设其他参数」的原文在
  缺省下仍然成立。当前 `.env` 显式设为 `false` / `128000`。
- **上限取 128k 而非 64k 的理由**：业务流中观察到过 80k 左右的输出；常用模型的上下文窗口
  均为 1M，128k 输出不超限。
- **附带发现**：异常检测不看 `finish_reason` 是一个独立的缺口，记录于此备查。

## 为什么不选另一条路

| 方案 | 结论 |
|---|---|
| 严格照搬定义文本 | **否决。** 等于把一个已知的静默丢数据缺陷带进新实现。三处偏离的共同特征是「失败不报错」：字段恒空、解析退化为空 dict，运行都是 `succeeded`。这类缺陷一旦上线，无法从运行状态上发现 |
| 照搬但只在代码里改，不留登记 | **否决。** 偏离会成为「没人知道为什么这里和定义不一样」的历史遗留。登记后，日后业务方在平台侧也修了同一处，登记的原文片段会「找不到」而让校验报错退出——这是想要的失效方式，提示复核 |
| 把偏离推给业务方改 DSL | **否决（本轮）。** 已确认由实现侧承担并登记。若日后平台侧同步修正，应回到「正文逐字符一致」的默认口径 |

## 代价与后续

- 三处偏离各自需要一个回归用例锁住行为，已分别落地。
- 偏离清单是**活文档**：新增偏离必须在此登记理由，不能只在代码注释里说明。
- 迁移前的 DSL 导出文件与台账已删除，本 ADR 是这批修订的唯一文字记录。日后若要与平台侧
  原文对账，需要重新取得 DSL。
