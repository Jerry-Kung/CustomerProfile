**任务目标**：
我是一名汽车销售顾问，刚刚认识了一位可能有购车意向的潜在客户。我从公开的合法渠道获取了该客户的一些信息（例如微信主页，朋友圈截图等），并为这位客户构建了一幅"个人特征画像"。另外，有些客户当前已经与我们的销售人员进行了电话联系，或者已经到店里进行了意向车型的试驾，我提供的信息输入包中可能包含该客户的通话录音及试驾录音相关的信息。我想要基于这些信息对该客户进行"商机等级分析"，即评估一下该客户大致的购车订单成交概率，以及该客户是否值得销售人员优先进行后续跟踪。

本任务要求：**证据不足时不抬级、不抬概率；有充分正向证据时允许客观上探；结论表述应对销售可执行，避免消极放弃话术。**

---

**【核心原则】**

1. **评级锚定（双模式）**

   **模式一：有原始评级（original_level）**
   - F/暂败/战败/无效等非 ABC，按 C 处理；
   - 原始评级为参考锚，不是硬天花板；
   - 信息有限/严重不足时，最终评级必须等于原始评级，不得上调下调，summary 标「待验证」；
   - 信息充分且满足第2步升级条件时，按证据化评分落档，允许跨档上探（如 C→A），不以「最多上调1档」限制；
   - 信息充分且存在明确负向证据时，允许按得分低于原始评级落档。

   **模式二：无原始评级**
   - 不以“有通话/试驾”自动抬高评级；
   - 最终评级由证据化评分决定；
   - 交互证据若显示“仅参考/推迟到店/明确拒绝”，必须按真实意向落低档。

2. **信息充分性（内部判断，不单独输出字段）**
   - **充分**：有通话/试驾/明确表态等直接交互，且至少覆盖3个评分维度；
   - **有限**：仅社媒/画像/留资，或短时交互无法稳定覆盖3维；
   - **严重不足**：仅姓名、手机号、渠道等极少字段。

3. **证据驱动（禁止推测加分）**
   - 加分必须有可引用的原话、行为或可验证事实；
   - “可能/或许/推测/大概率”不得作加分依据；
   - 信息缺失（社媒不可见、企业未命中等）不加分也不扣分；
   - 画像中的人设/兴趣/职业/管理者/通勤减负等，不能单独支撑匹配度或商机价值加分；
   - 禁止把画像推断需求写成与车型“高度匹配”。

4. **客观保守，而非消极否定**
   - 边界分档取较低档；默认取证据支持区间中低位；
   - 禁止“虽然证据有限，但考虑到……因此给高分”；
   - **C级 ≠ 放弃**：表示当前优先级低或窗口未到，应建议低频养线索/待验证跟进，而不是“无价值、不必跟”；
   - **信息不足维持原评级**时，须在 summary 标明“待验证”，提醒销售勿当已确认高意向。

---

**评估流程**

**第0步（内部）**：确认是否有原始评级 → 判定信息充分性 → 确定是否可按证据上探及概率约束。

**第1步：线索标准化评分（满分100，阻力为负）**

1.1 客户-产品匹配度（40）
- 明确表达的需求与卖点高度一致：30-40
- 2-3个可验证匹配点：20-30
- 间接匹配、确定性低：10-20
- 不明确或仅画像推测：5-10
- 有通话但未提具体需求/关注点：仍取5-10（低值）

1.2 客户商机价值（20）
- 有直接证据（高配询问、明确预算等）：15-20
- 有可验证高净值/升级线索：10-15
- 间接推测：5-10
- 证据极弱：0-5
- 不得因“忙碌/边界感/职场感”推断购买力：取0-5

1.3 需求/兴趣明确度（20）
- 明确购车需求或浓厚兴趣：15-20
- 可验证信号（问价格/配置/交期）：10-15
- 模糊意向（留资/浏览）：5-10
- 冷淡/不感兴趣/仅参考：0-5

1.4 跟进可执行性（20）
- 明确近期计划，或已到店/试驾/要求报价：15-20
- 可验证切入点（主动留资、回电、问具体信息）：10-15
- 有潜在方向但无时间意愿：5-10
- 无意愿/拒绝/无响应/明确推迟到店：0-5

阻力扣分（0到-20）  
须有明确证据；不得因社媒缺失或“品牌调性可能不匹配”扣分。
- 严重阻力（明确拒绝、竞品已定、严重错配）：-12到-20
- 较强阻力（预算不足、时间冲突、暂不考虑）：-6到-11
- 一定阻力：0到-5
- 无明确阻力：0

**第2步：商机等级**
- >50 → A；20<得分≤50 → B；≤20 → C

约束：
- 信息有限/严重不足且有原始评级：维持原始评级，不得上调；
- 信息充分时按得分落档；上探至高于原始评级须同时满足：①信息充分；②至少2维有直接表态/行为；③至少具备：明确时间窗 / 明确预算或支付准备 / 已到店或试驾且正向反馈 之一（允许一次跨多档，如 C→A）；
- 无原始评级时按评分落档，仍须证据驱动。

**第3步：成交概率**
在最终等级允许区间内取值（最近5%的倍数，最小5%）；禁止低等级给出越档高概率；禁止用画像/侧写加减概率。

| 最终等级 | 允许区间 | 档内基线 | 说明 |
|----------|----------|----------|------|
| A | 40%-80% | 50% | 信息不足的A取40%-50%并标「待验证」；默认不超过65% |
| B | 20%-40% | 30% | 常规培育带 |
| C | 5%-20% | 10% | 低优先/窗口未到，不是“没希望” |

定位方式（档内滑动，不抬级）：
- 以档内基线为起点；有可验证关键信号则加减（每项约±5pt）：正向如明确车型、问价/交期、约/已试驾到店、明确预算或时间窗；负向如拒绝、竞品已定、挂断失联、明确推迟且无窗口。
- 信息有限/严重不足：结果偏区间中低位；A最高分别不超过60%/50%。
- **A冲高至70%-80%**须同时满足：信息充分；≥3项正向关键信号（其中须含试驾/到店、明确时间窗、预算/支付准备、交定意向之一）；无强负向信号。否则A封顶65%。

**任务输出**
只输出：`business_score`、`business_opp_level`、`closing_probability`。  

`business_opp_level` / `closing_probability` 必须含：
```
"reasoning_detail": {
  "steps": [...],
  "summary": "xxx",
  "evidence": [...],
  "confidence": 0.95   // 本条推论的可信度（0~1），非信息充分性档位
}
```

要求：
- steps 覆盖：原始评级有无、信息充分性、是否可上调/应否按低意向落档、概率为何落在该位置；
- evidence 用自然语言，禁止证据ID与JSON字段名；必须来自原始证据；
- 证据不足上调时写明：“无充分证据支撑评级上调，维持原始评级X”或“无充分证据支撑更高评级，按实际意向评定为X”；
- summary 对销售可执行：低意向写清“低频养线索/等待窗口”；信息不足的原评级A/B写清“待验证，勿按已确认高意向推进”；
- 对外 reasoning 禁止出现“评分/分数/分数总和”等用语；
- confidence：表示推论的可信度，取值 0~1。它衡量的是“现有证据对该判断的支撑强度与稳定性”。

**注意事项**
- 简体中文；纯 JSON；可被 json.loads() 解析；不要用代码块包裹。
- 严禁：

  - × C级/低概率就写“无跟进价值、建议放弃”
  - √ 当前证据为……，充分性为……，因此评定为……；建议……跟进节奏
