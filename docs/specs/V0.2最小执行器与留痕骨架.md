# Customer Profile V0.2 设计与任务拆解

> 版本：V0.2　状态：已完成（2026-09-23，145 项测试全绿）
> 依据：`docs/specs/V0迁移规划.md` §3「V0.2 最小执行器与留痕骨架」、`Dify迁移任务说明.md`（§4–§7）。
> 上游基线：V0.1.1 台账（`docs/specs/ledger/`）。本文只写 V0.2 的设计意图与验收口径，不重复代码细节。

## 1. 目标与范围

**目标**：在小型真实拓扑上跑通「定义 → 调度 → 执行 → 落库 → 查询」。

**载体**（规划 §3 V0.2 指定）：

| 载体 | 规模 | 验证什么 |
|---|---|---|
| `（新）SubAgent - 猛士IT系统数据信息` | 4 节点 / 3 边，纯 code | 确定性逻辑等价 |
| `（新）SubAgent - 人工确认信息提取（生产环境）` | 4 节点 / 3 边，1 个 GET | HTTP 读取与留痕 |
| `synthetic_fanout`（人工构造） | 9 节点 + 3 节点子流程 | 并发、汇合、父子调用留痕 |

**明确不做**：不接真实模型；不做只读前端；不做生产保障；不迁移其余 16 个工作流。

## 3. 关键设计决策

### 3.1 两级独立信号量（父子不互等）

| 信号量 | 限制什么 | 谁申请 |
|---|---|---|
| `active_slot` | 同时执行的**节点**数 | 仅顶层运行的节点 |
| `request_limiter` | 同时进行的**真实出网请求**数（LLM + HTTP 共用） | 所有实际请求，含子流程内部 |

**为什么**：父节点若在执行名额内等待子流程，而子流程也要名额，上限为 1 时必然死锁。
实现上子运行一律**不申请** `active_slot`（`RunRequest.is_child=True`），只让它的真实
请求走统一限额。这同时满足「全局请求限额覆盖子工作流」与「父子不互等」两条硬约束。

### 3.2 固定响应回放分两层

| 层 | 匹配键 | 注入点 |
|---|---|---|
| LLM | `SHA256(model + messages)` | `LlmClient` 的 `replay` 参数 |
| HTTP | `METHOD url` | `HttpClient` 的 `replay` 参数 |

同一个请求可按出现序号排队多个响应，用**同一条固定请求的多次尝试**验证重试逻辑。
另挂一个 `httpx.MockTransport` 兜底返回 599，确保回放模式下**不可能**出网。

严格模式（缺省）未命中直接失败。宁可失败也不要静默返回空响应——后者会让「没跑通」
看起来像「跑通了」。

### 3.3 重试下沉到 `llm_call()`

按规划 §6.3/§6.4：17 处 `Gemini（异常输出重试版）` 调用点归一为一次调用，重试在
`llm_call()` 内部，最多 3 次尝试（差异清单 M1 缺省口径）。异常判定沿用原 DSL 判断
节点的四条规则；`usage` 缺失时**不**触发 `usage_zero`——把「未知」当成 0 是伪造。

因重试不再由图结构自然分开，**每次尝试必须由代码显式写入 attempt 表**，这是
规划 §6.6 特别点名的要求。

### 3.4 子流程即嵌套运行

`tool` 节点 → 一次嵌套 run，带 `parent_run_id` / `parent_node_id` / `call_path`
（形如 `/0/2/1`）。同一静态节点 ID 被复用多次时静态 ID 不足以唯一定位，`call_path`
可以。运行树自引用存于同一张表，V0.4 据此下钻到每一次尝试。

### 3.5 失败传播

前置失败 → 下游整片标记 `blocked`，**保留已完成结果**，运行判为失败。不做自动续跑：
「复用已保存结果重试」比全图恢复更优先（`Dify迁移任务说明.md` §7.3）。

### 3.6 定义层不承载控制流字符串

`if-else` 的条件写成 `{"field": 入参名, "operator": "...", "value": ...}` 的声明式结构，
不保留节点 ID 寻址，也不在定义里塞可执行字符串（规划 §6.2）。未知操作符直接报错，
不做「默认放行」。

## 4. 与 V0.1 台账的关系

`tests/test_ledger_crosscheck.py` 把「对照 DSL 结构逐项一致」变成可执行断言：
节点 ID 集合、节点类型、直接前置、边集合、code 节点入参绑定来源，逐项比对
`docs/specs/ledger/node_ledger.json`。

**只对 V0.2 已迁移的两个工作流断言**，不假装覆盖其余 16 个。

有意差异在测试中显式断言，避免日后被误当成缺陷：

| 差异 | 断言位置 |
|---|---|
| W4：`llm_model` 入参删除 | `test_mengshi_llm_model_input_is_dropped` |
| 明文密钥不进入定义 | `test_dsl_secret_is_not_in_definition` |

## 5. 验收标准与证据

| 验收项 | 证据 |
|---|---|
| 对照 DSL 结构，节点/边/变量映射逐项一致 | `test_ledger_crosscheck.py`（台账交叉核对） |
| 固定响应下，两个真实工作流输出与人工推算一致 | `test_mengshi.py`（手算期望值）、`test_human_corrected_info.py` |
| 迁移后的 code 逻辑逐字符等于 DSL 原文 | `test_code_verbatim.py`（AST 取函数体比对） |
| 多前置汇合只执行一次 | `test_join_node_executes_exactly_once` |
| 分支不设全局屏障 | `test_branches_run_concurrently_without_global_barrier`（用执行区间重叠证明，不用耗时印象） |
| 并发限额生效 | `test_active_nodes_respect_limit` |
| 每节点、每次外部尝试都有记录 | `test_full_run_records_all_four_layers` |
| 历史运行绑定当时的定义版本 | `test_run_binds_definition_version` |
| 父节点等待子流程期间不占用子流程名额 | `test_no_parent_child_deadlock_with_single_slot`（名额为 1 时不得死锁） |

运行方式：

```bash
pip install -r requirements.txt
python -m pytest
```

当前结果：**145 项测试通过，0 失败**。其中依赖 `dify_dsl_data/` 的比对测试在 DSL 缺失时
跳过并说明原因，不伪装成通过。

## 7. 配置增量

`.env` 新增（模板见 `.env.example` §6）：

- `REPLAY_MODE`：`off` / `fixture`。`fixture` 时 LLM 与 HTTP 全走固定响应。
- `REPLAY_STRICT`：未命中是否直接失败，缺省 `true`。
- `FIXTURE_DIR`：固定响应目录。
- `DATA_DIR`：数据目录（SQLite 落位于此）。
- `INTERRUPT_ON_START`：启动时把残留的 `running` 标为 `interrupted`。
