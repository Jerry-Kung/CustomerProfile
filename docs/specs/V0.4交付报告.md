## 2. 验收标准核对

| 标准（迁移说明 §8） | 结论 | 证据 |
|---|---|---|
| 前端拓扑与后端定义同源，不存在第二份拓扑 | 通过 | 前端无任何布局计算（grep 确认），坐标只取自 `definition.layout`；分层算法在 `layout.py`，由 12 项 Python 测试覆盖 |
| 历史运行展示当时的图与提示词版本 | 通过 | 详情页只走 `/runs/{id}/graph`，图来自 `definition_versions` 快照；`test_a_new_definition_version_does_not_change_an_old_run` 行为级验证：登记内容不同的新定义产生新版本后，旧运行仍指向原版本、节点集合不含新节点 |
| 子运行可下钻，能看到每次尝试 | 通过 | 节点级尝试端点 + `child_runs` 索引；`test_node_attempts.py`(7) 与 `test_run_graph.py` 的下钻断言 |
| 执行顺序不把并发伪装成线性 | 通过 | `RunTimeline.tsx` 按真实起止绘制并与依赖图并排切换；`test_node_timing.py` 断言重叠可被算出 |
| 密钥始终屏蔽 | 通过 | `redact_headers` 在写记录前掩码；`test_human_corrected_info.py:187` 行为级断言 |

**过程中发现并修复的三个真实缺陷**（测试全绿时全部漏过，都是「路径没被走过」）：

1. **`attempt_count` 恒为 0**（v0.4.3 修）。它是详情页判断「要不要拉尝试」的依据，
   而后端从无生产代码写它。修复采用**派生**而非自增——`fork_iteration` 复制父上下文
   的 `call_path`，按 `node_ref.call_path` 自增会更新到零行，静默失效。
2. **节点 `started_at_ms` 语义错误且从未落库**（v0.4.4 修）。被写成与 `duration_ms`
   同一表达式（耗时而非时间戳），且 `upsert_node_execution` 的冲突更新列表里没有这一列。
   没有它，执行顺序视图无从绘制——正是 V0.4 的验收要求。
3. **设计文档的「迭代节点带环」判断不成立**（v0.4.1 修）。实测 20 个定义全部无环。
   据此走过的两条弯路（DFS 回边断环、有界松弛声称能忽略回边）均被实测否定，
   最终按 DAG 设计并以环普查测试拦截。
