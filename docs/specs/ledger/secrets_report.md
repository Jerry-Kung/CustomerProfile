# 脱敏确认与密钥轮换建议

> 版本：V0.1.1　范围：本地 `dify_dsl_data/` 的 19 份 DSL 导出文件
> 结论口径：**如实报告实测结果，不接受规划文档中未经复核数字。**

## 1. 实测结果

**2 份不同的密钥值，分布在 5 个 HTTP 请求节点上。**

| 密钥（掩码） | 所属主机 | 节点位置 | 引用次数 |
|---|---|---|---|
| `sk-m9g...ypzE` | `https://mhero.dfmc.com.cn/customer_profile/m2m_api` | `（新）SubAgent - 人工确认信息提取（生产环境）` 节点 `1776649722195` | 1 |
| `sk-m9g...ypzE` | 同上 | `（新）SubAgent - 用户人工Feedback数据提取` 节点 `1779088846431` | 1 |
| `sk-cco...JsAp` | `http://118.145.238.50:8084/api/v1/remote` | `（新）SubAgent - 画像内容生成&回写（生产环境）（新）` 节点 `1776911410253`（`config/note-attributes`） | 1 |
| `sk-cco...JsAp` | 同上 | `（新）SubAgent - 画像内容生成&回写（生产环境）（新）` 节点 `1776912964274`（`callback/update-profile`，**有副作用**） | 1 |
| `sk-cco...JsAp` | 同上 | `（新）SubAgent - 证据线索汇总（生产环境）` 节点 `1775638961126`（`data/history/{phone}`） | 1 |

密钥以明文写在 HTTP 节点的 `headers` 字段中，形如 `X-API-Key:sk-...`（注意冒号后无空格）。

### 与规划文档的差异（须记入差异清单）

`docs/specs/V0迁移规划.md` §1.3 第 9 条与 §2.5 安全提示称「**4 处** HTTP 节点的 header 含明文 `X-API-Key`」。实测为 **5 个节点、2 个密钥值**。该数字口径混淆了「节点数」与「密钥值数」，两者都不等于 4。**以本节实测为准。**

## 2. 泄露面评估

| 问题 | 结论 | 依据 |
|---|---|---|
| 密钥是否进入 Git 历史？ | **否** | `git log --all -- dify_dsl_data` 无输出 |
| 是否已推送至远程？ | **否** | `dify_dsl_data/` 被 `.gitignore` 第 225 行忽略（实测 `git check-ignore` 命中），从未被跟踪 |
| 是否需要重写历史？ | **不需要** | 无历史提交包含该目录 |
| 实际泄露面 | 仅限**本地工作副本**：DSL 导出文件本身，以及任何曾读取它的本机进程/备份 | — |

**但仍须视为已泄露**：DSL 导出文件按其性质会被多人流转、邮件发送、上传到第三方平台。密钥一旦出现在导出物中就应假定不再安全。

## 3. 轮换建议与截止时间

| 项 | 内容 |
|---|---|
| 需轮换的密钥 | 2 个：`sk-m9g...ypzE`（mhero 中台）、`sk-cco...JsAp`（Notes / 回写服务） |
| **执行时机** | **在 V0 版本全部完成后手工执行**（用户 2026-09-23 决定，见 `differences.md` D7）。原「V0.3 接入真实 HTTP 之前」的建议已作废 |
| 是否紧急 | **不紧急**。V0 开发全程不触达生产外网（V0.2 仅在本地固定响应下运行），无即时利用窗口；风险在 V0 完成后统一处置 |
| 轮换后的落位 | 写入仓库根目录 `.env`（已被忽略），键名 `PROFILE_API_KEY`、`PROFILE_MHERO_API_KEY`，模板见 `.env.example`（不含真实值） |
| 轮换时的风险 | 旧密钥失效与新配置生效之间存在窗口；若 mhero / Notes 侧无并存期，轮换瞬间调用会失败。**须与运维或业务方协调切换时机**，本项目不掌握这两个服务的密钥管理权 |

## 4. 仓库受控文件的扫描结论

| 检查项 | 结果 |
|---|---|
| V0.1.1 入库台账（`docs/specs/ledger/*.json`）是否含完整密钥 | 不含。提取器只输出掩码，且 `verify_ledger.py` 把 `X-API-Key`、`sk-` 作为禁止子串校验，命中即失败 |

| `phone_numbers.txt` 是否入库 | 被 `.gitignore` 第 222 行忽略。**注意：文件当前含 20 个真实手机号，非空的 0 字节**（规划文档 §2.2 的 Q9 备注称其为空文件，已过期） |
| `.env.example` 是否含真实值 | 不含，仅有占位符 |
| `docs/` 下受控文档是否含密钥或真实手机号 | 未发现 |
