> 结论：**主入口端到端跑通**（`customer_profile_entry` 状态 `succeeded`，1282 s），
> 13 路扇出 **全部成功**，`result1` 为 27950 字字符串。

## 3. 冒烟发现的六个缺陷（测试全绿时全部漏过）

前四个来自第一波（2026-09-23 上午）；后两个来自第二波——AUC 改接云服务后，
录音类工作流**首次真正走到**单文件路径，才把它们翻出来。


按发现顺序，每次修复后重跑，逐层剥出下一个。

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | 17 个原 `gemini_retry` 节点报「既没有提示词入参 `prompt`」 | 子流程入参名是 `input_prompt`，执行器只认 `prompt` | 执行器同时接受两者 |
| 2 | 截图类流程抛 `JSONDecodeError`（对空串做 JSON 解析） | DSL 用边的 `sourceHandle` 区分 `if-else` 两支，迁移丢了这一位，**两支同时执行** | `NodeDef.branch_gates` + 调度层按实际分支门控；21 个节点补注解 |
| 3 | AUC 提交节点抛 `AttributeError: 'RunContext' object has no attribute 'get'` | `@body_template` 的引用替换调了不存在的 `ctx.get`；该路径零测试覆盖 | 改用 `ctx.resolve`；新增 `tests/test_body_template.py` |
| 4 | 视觉调用报 HTTP 400 `Download multimodal file timed out` | `_files_of` 用 `response.text` 编码 base64，二进制被文本解码改写（PNG 头 `iVBORw0KGgo` → `77+9UE5HDQoaCg`） | `HttpAttempt.response_bytes` + `_files_of` 优先用字节；fixture 支持 `bytes_base64`；录制脚本加 `--record-binary` |

| 5 | 录音流程报 `变量解析失败："模板变量 '1776135353554.file_content' 未提供；已提供：[]"` | `llm` 节点的模板正文引用 `{{#节点.字段#}}`，但节点未声明对应 `inputs`，渲染期变量表为空。同一处遗漏影响 **3 个声明点、共 10 个节点**（7 个截图类「多图片内容总结」+ 录音类的两个节点） | 3 个声明点补上绑定；新增 `tests/test_llm_template_bindings.py` 静态断言引用必被绑定覆盖 |
| 6 | 模型正确判出 `is_valid: true`，下游 code 节点却输出 `false`，**结论自相矛盾** | `expect_json=True` 的执行器把解析后的 **dict** 放进 `text`；两个消费方（`判断结果提取`、`Notes结果拆分`）都对 `text` 做 `json.loads`，传 dict 抛异常后被各自 `except` 吞掉、按缺省值返回，**静默给出错误业务结论** | `text` 改为 JSON 字符串（Dify 契约：llm 输出一律是文本），对象保留在 `parsed_json`；补 `import json`；新增 `tests/test_expect_json_output.py` |
**为什么单测没抓到**：缺陷 2 要真实数据才会走到「另一支」；缺陷 1 要真跑子流程才会经过；
缺陷 3 三个节点此前一个用例都没有；缺陷 4 的测试用的是 base64 字符串而非真实二进制。
教训：「覆盖了所有节点类型」不等于「覆盖了所有节点的取值路径」。

## 5. 覆盖度：如实标注未完成项

规划要求覆盖五类样本场景。用户 2026-09-23 决定**本轮只测 1 个号码、以打通端到端为目标**，
因此下表如实标注：

| 场景 | 是否覆盖 | 说明 |
|---|---|---|
| 信息完整 | ⚠️ **部分** | 测试号码在多数渠道无图片/录音，仅在 `wechat_search_homepage` 命中一个媒体文件 |
| 信息稀少 | ✅ 是 | 多数字流程走「无数据」分支并通过 |
| 无录音 | ✅ 是 | `test_drive_audio` 走无录音分支通过 |
| 格式异常 | ❌ **未覆盖** | 未准备异常格式样本 |
| 已知失败 | ❌ **未覆盖** | 未准备失败样本 |

**未覆盖的样本场景不做任何补偿性声明。** 样本矩阵留待后续版本。

## 7. 复核方式

```bash
# 端点可达性（AUC 已改云服务；不打印凭据值，只报「已配置 / 未配置」）
python scripts/probe_auc.py --all

# 复跑冒烟（强制关闭生产回写）
python scripts/smoke_run.py --workflow customer_profile_entry --read-timeout 1800

# 逐运行树查询（含每个子运行的成败与耗时）
sqlite3 data/customer_profile.db \
  "SELECT workflow_id, status, duration_ms FROM workflow_runs
   WHERE parent_run_id IS NOT NULL ORDER BY started_at_ms DESC LIMIT 20"
```

> 冒烟结果（含失败详情）同时落在那次运行的 SQLite 记录里——本报告的每个数字都可由
> `workflow_runs` / `node_executions` / `request_attempts` 三张表复核，不是手工统计。
