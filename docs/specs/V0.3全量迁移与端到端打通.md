## 1. 目标与范围

**目标**：把**全部 19 个工作流**（DSL 计 293 节点 / 324 边）迁移为 Python 定义，
补齐迭代、聚合（含分组）、vision 三类节点语义，并在测试环境端到端跑通主入口
`（新）客户初始画像（生产环境）`。

**明确不做**：不做只读前端；不做生产保障与并发压测；不做样本矩阵全覆盖（见 §6）。

## 3. 关键设计决策

### 3.1 迭代是普通 for 循环，但留痕必须逐项

`iteration` 节点折叠为串行 `for`（有意差异 P1：`is_parallel=false` 是权威信号）。
**但留痕不能跟着折叠**：循环体的静态节点 ID 每轮相同，而 `node_executions` 的唯一键是
`(run_id, node_id, call_path)`，不区分就是「多轮压成一条」，逐项追溯消失。

因此循环体的 `call_path` 覆盖为 `<父路径>/iter:<iteration_id>/<index>`，
由 `Scheduler.run_iteration_body_node` 统一处理。

**同类问题还有两处**，都是「数据库有、返回值没有」或「返回值有、数据库没有」的错位：

- 循环体执行记录须显式追加进 `RunOutcome.node_executions`——循环体不受父图调度，
  不经过那里的 append；
- `RunContext.resolve()` 须在循环体执行期间单独服务当前项（`(iteration, "item")`），
  因为此时迭代节点尚无产出，绑定解析拿不到值。

### 3.2 聚合的取值判据是「执行过」，不是「非空」

有意差异 P4。空串是合法产出（`无数据，输出默认信息` 模板的正常结果；各截图流程的
code 在未命中 channel 时明确返回空串）。若按「值非空」判定，这些**正常结果**会被当成
缺失，聚合器静默改用另一支的值——业务结果被改变而无任何报错。

分组形态（P3）每组包成 `{"output": 值}`：下游 code 取 `hobby_result_object["output"]`，
且这些入参在 DSL 里声明为 `value_type: object`。

### 3.3 提示词入参名沿用 DSL 的两个名字

`gemini_retry_2_times` 子流程的入参名是 `input_prompt`，17 处调用点原样保留；
迁移后新写的 llm 节点用 `prompt`。执行器**同时接受两者**，而不是把定义改名去迁就执行器。

这条是冒烟时踩出来的：只认 `prompt` 时，17 个节点全部以「没有提示词入参」失败，
而单元测试不会发现——它们不跑真实子流程。

### 3.4 回写默认关闭

新增 `WRITEBACK_ENABLED`，**缺省 `false`**（有意差异 W10）。置 false 时回写节点不发请求，
只产出「已跳过」的可解释结果，而不是伪造一个成功响应。测试、影子模式与真实冒烟都保持
false——V0.3 的验收目标是端到端**读**通。

### 3.5 提示词正文只有一个事实来源

运行期唯一来源是包内 `src/customer_profile/templates/`；`docs/specs/prompts/` 是评审副本，
由测试断言两边逐字符一致（有意差异 W11）。同一正文存在两处而无人校验，迟早会分叉。

## 4.1 真实冒烟发现的五个缺陷（单元测试全部漏掉）

这五个都不是环境问题，而是迁移错误。它们**在测试全绿的情况下**，只有接上真实模型、
走真实数据才暴露。分两波：前三个在 V0.3 首次真实冒烟（2026-09-23 上午）发现；
后两个在 AUC 改接云服务、录音类工作流**首次真正走到**之后发现（同日下午）。

记录下来是因为它们共同说明一件事：回放与微缩图验证的是「接线对不对」，真实链路验证的是
「接线在真实数据下会不会走错路」，两者不能互相替代。

| 缺陷 | 现象 | 根因 | 处置 |
|---|---|---|---|
| **分支门槛丢失**（最严重） | 截图类流程里「文件不存在」与「文件存在」**两条路同时跑**，后者对着空串做 JSON 解析，抛 `JSONDecodeError` | DSL 用边的 `sourceHandle`（`true`/`false`）区分 `if-else` 的两支，迁移只记了「有这条边」、丢了「走哪一支」 | `NodeDef` 新增 `branch_gates`；调度层按前置实际走的分支判定边是否失效；未走到的子树标 `SKIPPED`（与故障性的 `BLOCKED` 区分，不影响运行成败）。21 个节点补注解，`edge_list()` 保留 `source_handle` |
| **提示词入参名不匹配** | 17 个原 `gemini_retry` 节点全部报「既没有提示词入参 `prompt`，也未声明 `config['template']`」 | 子流程入参名是 `input_prompt`，调用点原样保留，而 llm 执行器只认 `prompt` | 执行器同时接受两者 |
| **`ctx.get` 不存在** | AUC 提交节点抛 `AttributeError: 'RunContext' object has no attribute 'get'` | `@body_template` 的引用替换写成了 `ctx.get(*parse_selector(...))`；`get` 是 `NodeResult` 的方法，`RunContext` 上没有，且该路径**此前无任何测试覆盖** | 改用 `ctx.resolve(...)`；新增 `tests/test_body_template.py`，按「引用在字符串外/内」两种语义分别钉住 |

| **`ctx.get` 不存在** | AUC 提交节点抛 `AttributeError: 'RunContext' object has no attribute 'get'` | `@body_template` 的引用替换写成了 `ctx.get(*parse_selector(...))`；`get` 是 `NodeResult` 的方法，`RunContext` 上没有，且该路径**此前无任何测试覆盖** | 改用 `ctx.resolve(...)`；新增 `tests/test_body_template.py`，按「引用在字符串外/内」两种语义分别钉住 |
| **模板变量未绑定**（10 个节点） | 录音流程报 `变量解析失败："模板变量 '1776135353554.file_content' 未提供；已提供：[]"`；截图类的「多图片内容总结」同因，只是视觉路径未被走到 | `llm` 节点的模板正文引用 `{{#节点.字段#}}`，但节点未声明对应 `inputs`，渲染期变量表为空。同一处遗漏影响 3 个声明点、共 10 个节点 | 3 个声明点补上绑定；新增 `tests/test_llm_template_bindings.py`，静态断言「模板里的每个引用都被绑定覆盖」 |
| **`expect_json` 把 dict 当文本** | 模型正确判出 `is_valid: true`，下游 code 节点却输出 `false`，两者矛盾 | `expect_json=True` 的执行器把**解析后的 dict** 放进 `text`，而两个消费方（`判断结果提取`、`Notes结果拆分`）都对 `text` 做 `json.loads`——传 dict 抛异常，被各自的 `except` 吞掉并按缺省值返回（`False` / 空列表），**静默给出错误业务结论** | `text` 改为 `json.dumps(...)` 字符串（Dify 契约：llm 输出一律是文本），解析后的对象保留在 `parsed_json`；补 `import json`；新增 `tests/test_expect_json_output.py` 钉住该契约 |
**为什么单测没抓到**：分支门槛要真实数据才会走到「另一支」；`input_prompt` 要真跑子流程才会经过；
`@body_template` 三个节点此前一个用例都没有。第 4 个缺陷的两条路径都要**真实输入**才走得到
（视觉路径要有图、录音路径要 AUC 可用）；第 5 个更隐蔽——它要求模型的判断**恰好与 `except` 的
缺省值相反**才会现形，此前的单方录音样本同样判「无效」，错误与正确无从区分。
教训是「覆盖了所有节点类型」不等于「覆盖了所有节点的取值路径」。

## 5. 迁移计数对照

| 项 | DSL（台账） | Python 迁移后 |
|---|---|---|
| 工作流（独立图） | 19 | **18**（`Gemini（异常输出重试版）` 归一，W2） |
| 节点 | 293 | **272** |
| 边 | 324 | **300** |

差额逐项对得上：

- 节点：−1（W1 入口冗余节点）−2−2（两个录音流的 gemini 侧 llm 节点）−5（人设特征判断的
  4 个 if-else + 纯 llm 支节点）−11（Gemini 子流程整图）＝ −21
- 边：−2（W1）−4−4（两个录音流）−11（人设特征判断，含被删分支）＋2＋2＋3（改用直接依赖表达）
  −10（Gemini 子流程整图）＝ −24

> 未折叠的类型（`iteration`、`variable-aggregator`、`if-else`、`template-transform`）
> 仍以节点形式存在——它们是**节点语义**，不是图形态，折叠会丢掉留痕与可追溯性。

## 6. 已知缺口（如实记录，不伪装为已覆盖）

1. **样本矩阵不完整。** 规划要求覆盖「信息完整、信息稀少、无录音、格式异常、已知失败」
   五类场景；本轮按用户决定**只测 1 个号码**，目标为打通端到端。未覆盖的场景见
   `ledger/v0.3_smoke_report.md`，后续版本补齐。
2. ~~**AUC 语音服务不可达。** `192.168.0.5:5005` 在本机网络环境下连接超时，因此两个录音类
   工作流的真实调用链路**未能验证**——它们的迁移正确性只有静态证据（台账交叉核对、
   code 正文比对、定义校验），没有真实模型证据。~~
   **已收口（2026-09-23）。** 内网服务长期不可达，按用户决定改接**火山引擎云服务**，
   由 `execution/auc.py` 做协议适配（云服务为异步提交 + 调用方轮询、状态在响应头
   `X-Api-Status-Code`、`task_id` 由调用方生成），**两个 HTTP 节点与下游两个 code 节点保持不变**
   （有意差异 W14）。`outbound_call_audio` 用真实录音端到端跑通：12 节点全成功、249 s，
   `is_valid=true` 走「有效」分支，产出 4904 字真实分析。
   该过程又暴露出两个迁移缺陷（§4.1 第 4、5 项），均已修复并补测试。
3. ~~`docs/specs/prompts/` 与包内资源不一致~~ **已收口（2026-09-23）。** W11 声称「两边由
   测试断言逐字符一致」，实测没有这个测试，且 81 份副本里 43 份与当时的 DSL 正文不同
   （V0.1 的副本用了另一套命名与抽取口径，且取自更早的 DSL 修订）。已按包内资源
   重新导出并统一命名，`tests/test_templates.py::test_review_copies_match_package_templates`
   断言两边逐字节一致——副本再失真，该用例会红。运行期只读包内资源，因此这一项本就不
   影响行为，属于评审产物的卫生问题。
4. **Qx 系列仍是缺省口径。** Q1/Q2/Q5–Q8 无外部结论，实现依缺省，**不等于等价验证通过**。
5. **M1 仍无外部结论。** 「最多 3 次尝试」是缺省口径。
6. **`@url_field` 未被任何节点使用。** 执行器文档提到它（URL 整段来自绑定值），
   但 19 个真实 http 节点无一使用，实际形态是「字面量 `@url` + `@url` 绑定拼接」。
   由 `test_real_image_http_nodes_use_literal_url_plus_binding` 钉住该事实。
