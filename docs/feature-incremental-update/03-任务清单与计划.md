本期只做 **T0 / T3**。没有增量推理，但先把「不变则不变」与基线归档兑现，风险最低。

### T1-4 调度入口工作流（两档）

## P3 · 取数链与灰度

### T3-1 快照导出连带基线

- `export_snapshot.py` 连带 `profile_baselines`，manifest 记行数。
- 验收：`tests/test_export_snapshot.py`；本地用快照起服务能看到基线并跑 T0。
- **实施说明**：
  - 只改 `export_snapshot.py`，**未改** `fetch_run_archive.py`。后者按 run_id 取单个包，
    基线是「按号码一行」的表、不挂在任何运行上，硬塞进包会让「一个包 = 一棵运行树」的
    口径破掉；要基线就走整库快照。
  - 基线按号码连带（给了 `--phone` 就只带这些），**不按时间窗**——基线没有历史版本，
    一个号码一行，「当时的状态」就是唯一的那份。
  - 源库没有这张表（P1 之前的库）时返回 0 而不报错：那是「没发生过增量」，不是损坏。
  - `FORMAT_VERSION` 升到 3。`format: 2` 的旧快照跑不出增量，只能复现 T3。

### T3-2 回放脚本支持序列

- `scripts/replay_incremental.py`；`replay_from_archive.py` 加 `--run-index`。
- 验收：对 `04` §2.1 的序列完整回放一遍，产出与 `compare_incremental.py` 对得上。
- **实施说明**：
  - 逐时点落 `experiments/uat_data/<batch>/t<N>/`，与真实跑批同构；`compare_incremental.py`
    指向某个 `t<N>` 即可。
  - `t1` **也必须走增量入口**：基线只由增量入口的 `baseline_commit` 写，`customer_profile_pipeline`
    里没有这个节点，让 t1 跑管线等于一轮都没写基线、从 t2 起全部退化成 T3 且不报错。
    两个 `--workflow` 都换成 `customer_profile_pipeline` 才能得到「同时点全量」对照组。
  - 每个时点把**归档运行的其余出网响应**一并铺进回放帧，再用夹具覆盖 history / profile。
    只用两个端点会让其他渠道全部落空，把「夹具不全」伪装成「增量失效」。
  - 转写条目按缓存格式原样复制，**不重算键**（键含识别参数，重算会整批静默未命中）。
  - 档位从 `nodes.json` 里 `incremental_dispatch` 的出参读，manifest 与预期档位并排。
  - 单测见 `tests/test_replay_incremental.py`（时点排序、夹具优先于归档、转写不重算、
    `--run-index`）。**真实模型的端到端回放尚未执行**，见下方「未完成」。
