## 〇、先回答三个前置问题

### 0.1 关于 `lead_rating`（清单 #2）

**结论：`lead_rating` 与 `intendedLevel` 是同一套七档字母体系，不是两套体系。**

| 判据 | 证据 |
| --- | --- |
| 值域完全相同 | `t_ods_leads_server_leads_info_rt.leads_level` 实际出现的值：H/A/B/C/O/F/L，与 `intended_level` 的 90461–90467 一一对应 |
| 字典同一分组 | 公共字典 `prefix_id = 1701`「线索级别」，值即 `H/A/B/C/O/F/L` 与 `无`，`sequence` 10→4（H 最热） |
| 数据规模印证 | 三门店线索表：F 36046 / C 4647 / B 1917 / A 1149 / L 329 / O 321 / H 28 条，与跟进表分布同构 |
| 老系统注释过时 | 「ABC 三档」是旧版口径，现行系统已扩为七档；`O` 是**原生取值**，不是异常 |

**`O` 的含义**：七档中介于 C 与 F 之间（`sequence = 6`），不是「Other/其他」的缩写，而是独立的意向档位。

**渲染建议**：`lead_rating` 可直接复用 `intendedlevel` 的七档标签，唯一差异是需额外支持 `无`（`prefix_id = 1701` 独有，表示尚未评级）。

### 0.2 关于 `status` 同名不同义（清单 #9）

**结论：三个渠道的 `status` 确为三套独立语义，请按 (channel, key) 二维查表，本文档也按此编排。**

| 渠道 | 字段 | 物理表 | 含义 | 值域 |
| --- | --- | --- | --- | --- |
| `OntologyLeadInfo` | `status` | `leads_info_rt.status` | 线索启用状态 | 0 未启用 / 1 启用 / 2 禁用 / -1 删除 |
| `OntologyTestDriveSchedule` | `status` | `test_drive_rt.status` | 试驾记录状态（软删标志） | -1 删除 / 1 正常 |
| `OntologyCustomerChatInfo` | `status` | `weixin_log.status` | 聊天记录状态 | 实测恒为 `1`（见 5.2） |

**`OntologyTestDriveSchedule.status = 1` 的准确答案**：它是**记录存活标志**，不是「试驾完成度」。实测 5324 条试驾记录**全部为 1**，取值为 1 只代表「该行有效、未被删除」，与线索的 `testDriveStatus`（0 未完成 / 1 完成）**完全无关**。此处清单 #9 的猜测需要修正——不要让画像层把它渲染成「试驾完成」。
