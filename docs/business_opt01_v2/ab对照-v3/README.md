> `docs/business_opt01_v2/` 下的一次**产物归档**，不属于文档主体。
> v2 首轮对照页见 `../ab对照/`，v2.1 整改后对照页见 `../ab对照-v21/`，本目录是 v3 三分层后的新版。

## 1. 这页是什么

v3 三分层管线（`customer_profile_pipeline`：L0 记录 → L1-1a 事实提取 → L1-1b 人设画像 →
L1-1c 分析投影 → L2 投影/兜底/审查 → L3 校验与表达）与基线（`customer_profile_entry`）
在**同一批 8 个用例**上的输出直接比对。

- 抽样：39 案中随机抽 8 案（20%），号码与 v2 / v2.1 两轮相同，可直接看三轮演进
- v3 批次：`experiments/abexperiments/batches/A-pipeline-L8-v3-20261013/`
- 基线批次：`experiments/batches/baseline-39-dsv41-noThink/`
- 上一版对照页：`../画像管线AB对照-v2.1.html`

**本页相对 v2.1 版只有一处呈现改动**：Notes 不再分「两边都有 / 仅基线有 / 仅 v3 有」三块，
而是把两臂按 `attribute_key` 求**并集**，排成一张两栏大表；某一侧缺该字段时，该侧单元格
**留空并高亮**（红色 ⊘ 标记），一眼可辨哪边有、哪边没有。逐案对照页进入即为这张表。

**Windows 注意**：含中文字面量的统计脚本一律用 `python -X utf8 <脚本>` 运行，不要用
`python -c "…"`——后者在 Windows 下按 ANSI 代码页解码，会让「审计词 / 冒号」这类中文比较

## 5. 两处必须知道的结果

**结果一：审计词泄漏 5 处，与 v2.1 同源，仍未闭合。**

5 处全部落在 **L2 兜底路径**（`merge_l2_verdict` 拼接的 `reason` 文本），分布在
`13530559591`（2 处：`age`、`annual_income`）与 `13829156876`（3 处：`family_structure`、
`driver_license_status`、`purchase_type`），命中词均为「社交自呈现」。文本形如
「兜底裁决：候选另一值来源为社交自呈现，置信为inferred_high，高于当前inferred_low，…」。

该文本由管线侧拼装，**不经过** `projection._plain_text` 的出口自净，故提示词层
与 `_to_notes_updates` 的约束都拦不住。v2.1 为 28 处，v3 降至 5 处（仅 2 案触发兜底），
但**未归零**。修复留待 v3 正式版：兜底裁决文本须走同一套出口自净。

**结果二：证据串「带出处」比例反而低于 v2.1（7/315 vs 46/311）。**

两轮的口径差异需说清：

- **v2.1** 的证据串多为「渠道：原文片段」形态（如「试驾录音信息：那是 I60 吧」），
  共 46 条命中该形态；
- **v3** 按设计稿 §4 接口一改造后，证据串改成了**自然语言描述 + 内嵌引号原文**
  （如「录音中提及『原来从月薪两三万…』的职业收入讨论」），不再以「渠道：」开头，
  故按旧口径统计只得 7 条。

**结论**：v3 的证据**含原文引用但形态变了**，旧口径（认「渠道：」前缀）已不适用。这是
**统计口径变化**，不是证据质量下降；但也说明 v3 的证据串**尚未收敛到统一的可解析形态**——
原始数据里的锚点改在 L1-1a 事实层（`anchor` / `source_quote`）承载，Notes 的 `evidence` 是
回收后的表述。若要按旧口径验收，须先在 v3 正式版定下新的证据形态契约。

  --workflow-id customer_profile_pipeline \
  --transcript-cache-dir experiments/transcript_cache \

结果为准**——批次目录每号码只保留最新产物。
