# v2.1 对照页（ab对照-v21）

> `docs/business_opt01_v2/` 下的一次**产物归档**，不属于文档主体。
> v2 首轮对照页见同级 `../ab对照/`，本目录是 v2.1 整改后的新版。

## 1. 这页是什么

v2.1 整改版管线（`customer_profile_pipeline`：L0 记录 → L1 取证 → L2 投影 → L4 分诊 → L3 成文）
与基线（`customer_profile_entry`）在**同一批 8 个用例**上的输出直接比对。

- 抽样：39 案中随机抽 8 案（20%），号码与 v2 首轮 `A-pipeline-L8-20261012` 相同，可直接看整改前后
- v2.1 批次：`experiments/abexperiments/batches/A-pipeline-L8-v21-20261013/`
- 基线批次：`experiments/batches/baseline-39-dsv41-noThink/`
- 上一版对照页：`../画像管线AB对照.html`（v2 首轮，含老问题复检四模块）

对照内容包括：两臂 Notes、两臂 9 个画像卡 section、L1 断言与投影明细、原始取数。

**本版页面只有两个模块**：总览、逐案对照。逐案对照的**首个板块就是 Notes 单边差异**——
按 `attribute_key` 做集合差，把「只在基线有」与「只在 v2.1 有」的字段分两栏列出，各带取值。

| 文件 | 内容 |

cd ab对照-v21 && python build.py
```

```

## 3. 数据敏感性与入库口径

`画像管线AB对照-v2.1.html` 与 `ab对照-v21/data/*.json` **含真实客户姓名、手机号、
企业名与录音转写**，属「真实客户数据」，**禁止入库**（口径见 `docs/business_opt01/README.md` §5）。
本目录的 `.gitignore` 已将其排除。

脚本与源文件本身不含客户数据，可正常入库。

## 4. 本批读数与两处必须知道的结果

| 读数 | 基线 | v2.1 | 说明 |
|---|---|---|---|
| Notes 条数 | 226 | **214** | 基线的 95%；逐案 0/29/23/42/0/36/42/42 |
| 画像卡条目 | 309 | **196** | 基线的 63% |
| Notes 单边字段 | — | — | 仅基线有 66 处、仅 v2.1 有 54 处、两边都有 160 处 |
| LLM 调用 / Token | 182 / 2,615,341 | **54 / 537,860** | 降约 70% / 79% |
| 证据锚点带原文出处 | — | 46 / 311 | 「渠道：原文」形态 |
| 审计词命中 | — | **28** | **未达归零验收线**，见下 |
| 「未知渠道」占位 | — | 0 | v2 首轮为 128 |

**结果一：2 案无 v2.1 产出，不计入质量结论。**

- `13435844484`：`l3_express` 连续 5 轮返回被截断的 JSON（约 7–8 千字符处断开），运行 `failed`。
- `17119850673`：运行 `succeeded`，但 L0 取数 15 条里 13 条 `exception`，L1 无材料、断言 0 条，
  Notes 与卡片为空。**属取数侧故障**，非管线缺陷。两案在页面上均单独标出，
  其「仅基线有」的字段数是整案基线字段数，不代表 v2.1 的召回缺口。

**结果二：审计词泄漏 28 处，是 v2.1 的未闭合缺陷。**

28 处全部落在 **L2 兜底路径**（`merge_l2_verdict` 在 `customer_profile_pipeline.py:1259-1261`
拼的 `兜底裁决：…` 文本），分布在 `19820803068`（9）、`13530559591`（9）、`13829156876`（10），
内容形如「兜底裁决：仅社交自呈现单一来源支撑，维持原值」——来源档代号与内部规则名被直接
写进销售可见的 `reasoning_detail.steps`。该文本由管线侧拼装，**不经过** `projection._plain_text`
的出口自净，故提示词层与 `_to_notes_updates` 的约束都拦不住。

`scripts/probe_v21_audit.py` 的离线回放读数为 0，是因为它把 L8 批次的 L1 原始输出喂回重算，
**不重跑 L2 兜底那次 LLM 调用**（施工任务书 §6 已列明该路径留待 AB 验证）。本批真实出网运行
把这条路径测出来了。

## 5. 跑批与重试

跑批命令（两臂共用 `scripts/run_baseline.py`，只用 `--workflow-id` 区分）：

```
python scripts/run_baseline.py \
  --out-dir experiments/abexperiments \
  --batch-id A-pipeline-L8-v21-20261013 \
  --workflow-id customer_profile_pipeline \
  --transcript-cache-dir experiments/transcript_cache \
  --only <8 个号码>
```

重复失败的号码**以最后一次入队结果为准**——批次目录每号码只保留最新产物。

## 6. 与 v2 首轮的数字口径差异

首轮读数 V2=190 / 基线=226（比值 0.84）测的是**改动前**的实现；本版测的是 v2.1 整改后，
两处数字不可混引。首轮把失败案也计入分母，本版按实际成功案统计并在页面上标出。
