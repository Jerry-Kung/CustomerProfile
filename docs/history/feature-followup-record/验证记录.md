## 三、人工核读

抽查了 `13016467834`、`13125000455`、`13264813352`、`13260565922`、`13121132715`、
`18986162155` 六案的全部输出，逐项核对：

- **排序**：与「跟进创建时间」一致，同刻记录按记录 ID 稳定排序。
- **无中生有**：未发现记录里没有的动作、承诺、车型或价格。
- **战败 / 转商机**：`13264813352` 第 3 节点命名「电话邀约暂败」、`13121132715` 第 4 节点
  「暂败登记（无法联系）」、第 5 节点「转商机跟进」，与 `extra_info` 中的
  `跟进结果` / `战败类型` / `是否转商机` 一致。
- **对客产出红线**：`contents` / `extra_info` 中无英文键名、无规则编号、无枚举裸码
  （如 `90451`）、无 `未知渠道` 类占位串。占位串与裸码在 `_literal` 里就被折成空串。
- **两段式**：首段为销售原文（连内部多个空格都保留），次段为模型补的整句陈述。

样例（`13016467834`，单条最小案）：

```
node_name: 首次电话邀约试驾
contents[0]: 电话没有接。。。。。。。            ← 销售原文，逐字
contents[1]: 2026年11月2日，销售顾问电话联系客户邀请试驾，客户未接听。
contents[2]: 客户意向车型为Max+，意向级别较高，已约定2026年11月9日再次跟进。
followed_at: 2026-11-02T17:29:49      followed_at_text: 2026年11月2日下午
extra_info: {跟进渠道: 电话, 参与人: [销售顾问朱奥然, 客户本人], 关联车型: Max+,
             跟进结果: 仍需后续跟进, 意向级别: B 级意向（较高）, 是否转商机: 否,
             下一步跟进: 2026-11-09}
```

## 四、开发期发现并已修复的两处缺陷

1. **`main()` 漏加入参** —— 节点定义绑了 `follow_up_json`，函数签名却没有，端到端直接
   `TypeError`。既有 `test_pipeline_end_to_end` 当场拦住。
2. **原文空白被折叠两处** —— `assemble` 与 `sanitize` 都用了「折叠连续空白」的清洗函数，
   把销售原文里的多个空格改成单空格。第一版实跑时靠「原文是否逐字出现在输出里」的核对
   才发现（`RAW_MISSING=1`）。已拆成 `_clean_verbatim`（原文：只去首尾）与
   `_clean_contents`（模型陈述：折叠），并补两条用例钉住。
