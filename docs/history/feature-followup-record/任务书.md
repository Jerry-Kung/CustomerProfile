# 任务书：客户跟进履历（`follow_up_history`）

> 立项日期：2026-11-16　开发目录：`docs/feature-followup-record/`
> 方案依据：本目录 `方案设计.md`（已批准），业务契约 `docs/reference/AI画像回传接口变更说明-客户跟进履历.md`

## 0. 一句话目标

在业务测试臂（`customer_profile_pipeline`）上新增一条**并行的**跟进履历产线，
用 1 次独立 LLM 调用把「销售跟进记录」归档成时间线，随 v2 回传体
`analysis_result.follow_up_history` 回写；无记录时零调用、不出键。

## 1. 已锁定的口径

| 项 | 定论 |
|---|---|
| 开关 | **不加**。不引入任何环境变量，本特性始终执行（用户 2026-11-16） |
| 数据源 | 仅 L0 记录层的 `OntologyLeadFollowRecord`（「销售跟进记录」），不另开取数口 |
| 调用位置 | 与 L1/L2/L3 并行，`after=(L0_RECORDS,)`；不增加关键路径时延 |
| 节点类型 | `code`，内部调 `llm_call`。**不用 `llm` 节点**（失败会阻塞下游子树） |
| 分工 | 代码管结构/排序/上限/时间归一/`extra_info`；模型只管节点命名与 `contents` 可读化 |
| 模型失败 | 代码兜底：记录 1:1 出节点，仍出键 |
| `contents` | 两段式：首段原样保留销售原文，次段是模型补的可读陈述 |
| `id` | `fu-{sequence}` |
| 无数据 | **键不出现**（绝不输出 `[]`——那是「清空」语义） |
| 增量 T0 | 原样回传上一版，本特性不参与 |

## 2. 交付物与顺序

按此顺序做，每一步可独立验证：

**T1 · 解析与结构（纯代码，可先离线跑通）**
- `build_follow_up_records(records_json)`：从 L0 `records_json` 筛出跟进渠道、
  按「跟进创建时间」升序、行解析出目的/方式/结果/意向级别/车型/顾问/下次跟进时间。
- `assemble_follow_up(parsed, model_out)`：节点生成、`id`/`sequence`、上限截断、
  未覆盖记录的代码补节点。
- `sanitize_follow_up(nodes)`：契约自检（§3.5 五条），返回 `(nodes, dropped)`。
- 全部为普通同步函数，不触网。

**T2 · 提示词与调用**
- 新增 `templates/customer_profile_pipeline__pipeline_follow_up.txt`。
- `build_follow_up_history(records_json, llm=None, templates=None, node_ref=None)`：
  空输入短路 → 渲染 → `llm_call(expect_json=True)` → 解析 → 装配 → 自检 →
  失败兜底。出参见方案 §3.3。

**T3 · 接线**
- `pipeline` 新增 `FOLLOW_UP` 节点常量与节点定义，`CODE_SPECS` 登记。
- `callback_build.build_analysis_result` 增加 `follow_up_json` 入参，
  `build_follow_up_history` 区块构造器，`main` 透传。
- `callback_build` 的 `CALLBACK_BUILD` 节点改绑 `follow_up_json` 与 `after`。
- `runner._checker_functions` 注入 `build_follow_up_history` 的 `llm`/`templates`。

**T4 · 测试**
- 新增 `tests/test_follow_up_history.py`：解析、合并、上限、自检五条、跳过分支、
  失败兜底、对客产出红线（无内部键名/裸码）。
- 改既有断言：`test_analysis_result_never_exceeds_the_six_contract_keys` → 七键；
  `test_callback_nodes_exist_in_the_business_test_arm` 的 `predecessors`。

**T5 · 文档**
- `docs/design/客户人设画像管线设计.md`：§2 流程图 + 成本分布、§5 输出契约六键 → 七键。
- `docs/changelog.md` 一条。
- 本目录 `验证记录.md`：八案实跑结果与人工核读结论。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 一条非法 `followed_at` 让整次回写 400 回滚 | T1 的自检就是回写前的最后一道闸，单测逐条覆盖 |
| 模型把节点数拉爆或漏掉记录 | 上限在代码截断；未覆盖记录代码补节点 |
| 模型编造不存在的动作 | 提示词约束 + 自检拒绝任何无法锚定到输入记录的节点 |
| 回放时录音位为空影响整案 | 本分支只读文本渠道；带录音两案只看履历区块，不横比九板块 |
