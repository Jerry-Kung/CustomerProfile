# 项目清理报告 (v3.3 基线)

## 清理时间
2025-01-16

## 清理背景
发现LLM调用时出现**疯狂的持续性缓存写入**现象：某段时间内几乎每个请求都带上了300k的缓存写入，导致异常费用开销。怀疑频繁跑批实验带来的历史数据/脏数据造成了上下文污染与崩溃。

## 🚨 疑似根本原因

**`src/customer_profile/templates/` 目录的历史模板堆积**

- 原有模板文件：**83个**
- 其中历史版本：**78个** (带时间戳的废弃模板)
  - `customer_profile_production__*.txt`: 19个历史版本
  - 其他各类模板的多个带时间戳版本

**推断的问题机制**：
如果代码在某种情况下遍历或批量加载了这些历史模板文件，会导致：
1. 每个请求携带大量重复的历史模板内容
2. Anthropic的prompt caching机制尝试缓存这些内容
3. 如果每次请求的模板组合略有不同，就会**持续产生新的缓存写入**
4. 这正好解释了"几乎每个请求都带上了300k的缓存写入"
