# 证据链与推理链可读性优化方案

> 状态：**已收口**（2026-10-19 整改完成，见 `docs/changelog.md` 同日条目）。

> 起因：测试环境（18173）实测，部分字段的「信源原文匹配」只写渠道名、「逻辑推导链」写
> 「来自某渠道」，对销售完全不可理解；另有字段的信源与结论风马牛不相及。
> 本文记录口径、根因与改动边界。管线总体设计见 `客户人设画像管线设计.md`。

## 1. 对客口径（硬约束）

对客产出的 `reasoning_detail` 只有两个字段面向销售：

- **`evidence`（信源原文匹配）**：必须给出**信源原文是什么**，不能只写取自哪里。
  可接受：客户原话切片、登记字段的具体取值、第三方标签名与取值。
  不可接受：裸渠道名（「手机号归属地信息」）、记录编号、JSON 键名。
- **`steps`（逻辑推导链）**：以可读为第一优先级。能一句话说清就一句话；推理确实复杂时
  才分步，每步必须有信息量。禁止把依据换一种说法再抄一遍。

`evidence` 为空时前端不渲染该区块；宁可留空，也不输出渠道名占位。

## 2. 根因（39 案实测）

| 现象 | 根因 |
|---|---|
| 第三方标签字段证据只到标签名 | L1 提示词只要求写标签名，标签取值从未进入证据。163/163 全中 |
| 「行业」证据只有渠道名且渠道错误 | 锚点含 `**` 加粗，逐字定位失败；且 `手机号归属地信息` 与 `关联企业信息` 在 `bundle_channels` 里接了同一份企业注册信息 |
| 「现车信息」证据与推理只有渠道名 | 锚点跨句拼接（`家用有旧车吗？首购`），定位失败后既无引文也无依据，渲染退到渠道名 |
| 注入字段（手机号/驾照）证据只有渠道名 | 注入断言本身不带依据文本，渲染只能输出渠道名 |
| L2 兜底补的字段无证据 | `merge_l2_verdict` 新建条目时 `evidence` 固定为空 |

实测基线（v3.3，39 案 1564 字段）：证据位只有渠道名 7.4%，推理链为「来自X」5.4%，
第三方标签证据带取值 0%。

## 3. 决策

1. **证据生成交给模型，校验留在代码。** 提示词要求模型给原文连续片段；代码仍校验
   该片段是否逐字存在，未通过的片段不得展示。不做整篇录音按句切分再拼接引文。
2. **容错只做低风险项。** 代码允许忽略 Markdown 加粗与标点差异；不做模糊/有序字符
   匹配（实测仅救回 2% 且会把不相干文本认成证据）。
3. **取值回查限同渠道。** 锚点失败时可用字段取值在同一渠道原文里回查；跨渠道回查
   会把别的渠道里同值文字误当证据，不做。回查结果只作证据展示，不升级置信档。
4. **推导链不强制一句。** 判断权交给模型：简单推理一句，复杂推理分步。
5. **定位失败不丢字段。** 维持降级保留；牺牲的是证据质量，不是结论。

## 4. 验收指标（8 案小批次对照）

| 指标 | 基线 | 目标 |
|---|---|---|
| 证据位只有渠道名 | 7.4% | < 1% |
| 推理链为「来自X」 | 5.4% | < 1% |
| 第三方标签证据带取值 | 0% | 100% |
| 有锚点且渠道有原文时逐字命中 | 92.1% | ≥ 97% |
| 定位失败导致字段丢失 | 20/550 | ≤ 5 |

## 5. 改动边界

- 提示词：`pipeline_l1_facts`、`pipeline_l1_fields`。
- 代码：`projection.py` 的出口渲染；`customer_profile_pipeline.py` 的定位容错、
  渠道拆分、L2 兜底证据。
- 不在本轮：按句切分录音、跨渠道取值回查、模糊匹配。
