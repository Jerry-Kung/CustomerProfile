# Phase 06 执行 Prompt：发布与运维准备

> 历史资料：记录编写时的设计与操作方式。当前实现和部署请从[文档导航](../../README.md)进入。


## 目标与边界

本阶段完成上线准备，建立可运维、可观测、可回滚的交付能力。

- 目标：
  - 产出启动参数、部署清单与环境检查项
  - 定义关键指标与告警阈值
  - 编写故障处置 Runbook
  - 明确灰度发布与回滚策略
- 边界：
  - 不改动核心业务流程与合同定义
  - 不引入与当前规模不匹配的复杂平台改造

## 输入上下文与实施约束

- 输入上下文：
  - 服务包含 API 进程与 Worker 进程双入口
  - 关键风险集中在 Dify 调用稳定性与队列堆积
  - 数据一致性依赖 MySQL 状态流转
- 实施约束：
  - 运维文档必须可执行、可复现，不仅是概念描述
  - 告警项必须覆盖可用性、延迟、失败率、堆积
  - 回滚策略必须说明数据兼容与操作顺序

## 产出清单

- 部署与启动文档（含 API/Worker 独立启动方式）
- 配置核验清单（敏感配置注入、依赖连通性、迁移状态）
- 指标定义与告警阈值建议（如成功率、`queued` 堆积、P95 处理时长）
- 故障 Runbook（Dify 不可用、DB 连接异常、任务卡死）
- 灰度发布与回滚手册

## 验收标准

- 新环境可按文档完成部署并启动 API/Worker
- 核心观测指标可采集，关键告警可触发
- 典型故障场景有明确处置步骤与恢复验证方式
- 灰度与回滚流程可在演练中执行
- 发布文档与当前实现版本一致

## 自检清单

- [ ] 启动参数、环境变量、迁移步骤已形成清单
- [ ] 指标与告警覆盖提交量、成功率、失败率、堆积与耗时
- [ ] 至少一次灰度/回滚演练记录
- [ ] Runbook 涵盖告警识别、止损、恢复、复盘

## 输出格式要求（执行后汇报）

1. 变更摘要（发布与运维文档）
2. 指标与告警阈值说明
3. 演练结果（灰度、回滚、故障处置）
4. 上线门槛结论与剩余风险
