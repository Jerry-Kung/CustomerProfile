# Phase 05 执行 Prompt：可靠性与测试强化

> 历史资料：记录编写时的设计与操作方式。当前实现和部署请从[文档导航](../../README.md)进入。


## 目标与边界

本阶段提升可交付质量，补齐测试矩阵与运行时补偿策略。

- 目标：
  - 完成状态机、解析器、校验器单元测试
  - 完成提交到回写主干链路集成测试
  - 完成失败注入测试（超时、非法 JSON、schema 不匹配）
  - 引入 `processing` 超时回收补偿策略
- 边界：
  - 不改变已冻结 API 合同与核心数据模型
  - 不引入与当前规模不匹配的复杂分布式组件

## 输入上下文与实施约束

- 输入上下文：
  - 任务状态机固定为四态
  - 业务主键唯一，重复提交触发覆盖
  - Worker 为长耗时执行主体
- 实施约束：
  - 测试需覆盖成功路径与关键失败路径
  - 补偿逻辑只能回收异常滞留的 `processing` 任务
  - 不能通过修改合同来“规避”测试失败

## 产出清单

- 单元测试：状态流转、output 校验、错误分类
- 集成测试：提交 -> 抢占 -> Dify 适配 -> 回写 -> 查询
- 失败注入测试：网络失败、超时、坏数据
- Worker 补偿任务：超时检测、状态回收、重试标记策略
- 基础质量门禁脚本（测试与静态检查）

## 验收标准

- 关键模块测试通过且失败场景可稳定复现
- 补偿逻辑可将超时 `processing` 任务转回可处理状态（或明确失败态）
- 错误码落库与 API 对外映射一致
- 任务幂等与并发行为在测试中得到验证
- 主干链路在无人工干预下可重复通过

## 自检清单

- [ ] 单元测试覆盖状态机与解析失败分支
- [ ] 集成测试覆盖至少一条完整成功链路
- [ ] 至少三类失败注入场景可复现并断言结果
- [ ] 补偿策略有可观测日志与保护阈值

## 输出格式要求（执行后汇报）

1. 变更摘要（测试与补偿相关）
2. 测试矩阵与覆盖说明
3. 失败注入结果与补偿验证结果
4. 残余风险与生产前建议
